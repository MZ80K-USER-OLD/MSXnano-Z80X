# V15 16bit indexed LD 検証データ

## ファイル

- `cases.jsonl`: 1行1ケースの入力と期待結果。
- `results.jsonl`: 同じ`id`に対応する実測値、合否、終了コード、失敗診断。
- `summary.json`: 実施日時、GHDL版、ソースのSHA-256、完了状態と合格数。

実行例 (リポジトリルート、GHDLが必要):

```powershell
& .\fpga\G80A\test\run_v15_index16.ps1
```

再実行すると、このフォルダの3データファイルを上書きする。
途中停止した実行は全件合格と扱わない。`summary.json`の`complete=true`と
432件の結果が揃っていることを確認する。強制終了ではsummaryが更新されないこともあるため、
保存する際は開始/完了日時と各ファイルも照合する。

## 対象とケース数

対象命令は、DD/FDプレフィクスによる次の12種。

| オペコード | 転送 |
|---|---|
| DD/FD 07 d | BCへ読出し |
| DD/FD 17 d | DEへ読出し |
| DD/FD 27 d | HLへ読出し |
| DD/FD 0F d | BCを書込み |
| DD/FD 1F d | DEを書込み |
| DD/FD 2F d | HLを書込み |

- M1/M2: CPU通常/Fast × MODE × IX/IY × BC/DE/HL × 読出し/書込み
  × 4アドレス条件 × WAIT有無 = 384ケース。
- M0: CPU通常/Fast × IX/IY × 6コード × WAIT有無 = 48ケース。
  プレフィクスなしのZ80命令との比較で互換性を確認する。
- 計432ケース。

## 入力の意味

- `initial.program_hex`: bank00の0000hから配置する256byteのメモリイメージ。
  実際にテストベンチが生成したバイト列であり、末尾の未使用領域は00。
- 初期メモリは原則00。`memory_00FFFF=EF`を設定する。
  M1/M2の読出しケースでは、`target_address`からEF BEも設定する。
- レジスタ準備は上記の命令列で行う。内部レジスタを外から直接書き換えない。
  RESETで規定されない汎用レジスタの全初期値を仮定するデータではない。
- 20ns周期のクロック、45nsでリセット解除。`ticks`は最初0で、
  リセット中を含むクロック立上がりごとに増加する。
- WAITありでは`ticks % 5 < 2`でWAIT_n=0、それ以外は1。
- 4アドレス条件は、変位00で01:FFFFからの2byte転送、変位FF(-1)で
  01:0000から00:FFFFへのborrow、変位80(-128)、変位7F(+127)。
- M0の`target_address`は比較用の組合せメタデータであり、転送先ではない。
  M0ではindexed LDを実行せず、元のZ80命令として動作する。

## 期待値と実測値

M1/M2では転送値BEEF、アドレス元IX/IY不変、F=D7保持、
対象ペアのバンク67保持、インデックスのバンク01保持を確認する。
書込み時は物理24bitアドレスと各バイト(EF/BE)、書込み回数2もアサートする。
読出し時は宛先の初期値1234からBEEFへの変化と、対象への書込みがないことを確認する。
24bit版追加時の共通テスト更新では、対象外ペアの下位16bitとバンクの保持も確認する。
準備値はBC=1357、DE=2468、HL=369Cから対象ペアだけ上記値へ置換する。
M0の比較ではAF'も命令列で準備する。

`results.actual`にはペア値・インデックス値・F・各データバンク・対象書込み回数を記録する。
ペア値とインデックス値は表示上の16bit数値であり、バイト列ではない。

M0ではプレフィクスなし/ありを同じ準備状態で実行する。
`actual.reference`が前者、`actual.state`が後者の結果で、並びは
`BC低,BC高,DE低,DE高,HL低,HL高,F,A`の8byte。
M0の期待値はこの比較実行による参照値であり、外部Z80エミュレータ由来の
独立した正解値ではない。

各結果の`passed`は、GHDLが正常終了し、実測レコードを出力し、
テストベンチ内の全アサーションが成功したときだけtrueとなる。
Fuseの全レジスタダンプ、メモリバスイベント列、厳密な命令クロック数の比較は
この版の対象外。Fuse用ツールへ直接読み込める形式でもない。

この形式は記録・機械比較用であり、GHDLはJSONを入力として読むのではなく、
[テストベンチ](../../fpga/G80A/test/tb_v15_index16.vhd)で生成した命令列を実行する。
命令列生成方法も変更した場合は、期待値とソースハッシュの両方を点検する。
