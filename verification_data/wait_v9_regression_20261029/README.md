## 配置配線後のタイミング

詳細・経路一覧・参照ファイルハッシュは[timing.json](timing.json)。

| PnR CLS使用量 | 9791/10368、95% |

最悪Setupは`clock_27m`からMCU側推定クロック
`fpga_companion_inst/mcu/n4_24`への経路。
最悪Holdは`clock_audio`から`clock_27m`への経路。
他にもresetをクロック扱いした経路、VideoDH/DLClkからSDRAM制御等への経路がある。
レポートにはresetとMCUクロックの未定義警告、`ex_clk_27m_d`の汎用配線警告もある。

クロック間の位相、resetの用途、CDC実装、SDCのクロック・例外指定を確認する必要がある。
今回のWAIT変更が原因だとも、すべて制約だけの見かけの違反だとも断定していない。
違反を消す目的だけでfalse pathやmulticycleの指定を追加してはいない。

**Fmax表が目標周波数を上回り、クロック別TNS表が0でも、
全体集計・詳細経路には違反がある。Fmax/TNSだけを根拠に合格にしない。**
Setupの経路表は最大400件、Hold/Recovery/Removalは各25件の出力制限があり、
報告経路数と違反端点数は別の数値である。

## 保存した機能確認点

[functional-snapshot.zip](functional-snapshot.zip)に、FPGAソース・制約・試験ランナー、
実機テストソース/手順、現行10本のCOM、既存FPGAイメージ、PnR証拠を保存した。
[snapshot-manifest.json](snapshot-manifest.json)に各ファイルのSHA-256を記録し、
ZIP内の全268エントリを読出してハッシュ一致を確認した。
これは対象ファイルのローカル保存であり、全リポジトリのバックアップではない。
保存時点で未コミット変更を含む。履歴用の旧試験ソースを含むが、実行可能という意味ではない。

- ZIP SHA-256:
  `D4458A3E4E74019E0F3397B39DE0E4D92B9BF50BD7EBDF657B783D47D4DAFD10`
- 保存した既存FPGAイメージSHA-256:
  `90DC27593A9ED53B1277269A1251F2FB3771ED9B9E3762760730DDC158DE8A91`

以前生成した別イメージのハッシュとは異なるため、同一物として扱わない。
ソース、プロジェクト設定、イメージの現時点での保存は行ったが、
既存ビルド時点の全入力と実機書込み対象の一致を遡及的に証明したものではない。
