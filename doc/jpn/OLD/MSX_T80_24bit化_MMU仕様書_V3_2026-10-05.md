# MSX T80 24bit化 MMU仕様書

**版:** V3  
**更新日:** 2026-10-05

## 1. 目的

本MMUは、24bit化したT80 CPUの論理アドレスを実機の物理メモリへ変換するための簡潔なbank変換機構である。

CPUの24bit論理アドレス空間は16MBであり、上位8bitを論理bank番号、下位16bitをbank内offsetとして扱う。

```text
Logical Address = { Logical Bank[7:0], Offset[15:0] }
```

論理アドレスとFPGA上の物理アドレスは同一ではない。M1/M2ではMMUを介して物理メモリへ変換する。

I/O空間は従来どおりZ80の16bit I/O空間であり、MMU変換の対象外とする。

---

## 2. 動作モードとMMU

### M0

- MMUを完全にバイパスする。
- CPUからは従来のMSX/Z80互換64KBメモリ空間が見える。
- slot、memory mapper等を含め、既存MSXのメモリ機構をそのまま使用する。

### M1

- 命令実行PCは16bitのZ80互換領域を使用する。
- 24bitデータアドレスに対してMMUを使用する。
- Z80互換SPは16bitであり、stackはbank 00のMSX互換空間を使用する。

### M2

- PC24および24bitデータアドレスにMMUを使用する。
- active stack pointerはMSP24。
- MSPによるstackアクセスもMMU変換対象とする。
- 既存Z80命令の16bit絶対メモリアドレスはbank 00として解釈する。

```text
16bit address xxxxH -> logical 00:xxxxH
```

例:

```text
LD A,(1234h)  -> 00:1234h
LD (1234h),A  -> 00:1234h
```

レジスタ間接によって24bitアドレスを生成する拡張動作では、対応する24bitレジスタ値を使用する。

---

## 3. Bank 00

論理bank `00h` は特別扱いとし、MSX/Z80互換64KB空間を表す。

```text
00:0000 - 00:FFFF -> MSX compatible 64KB space
```

この空間にはMSXのslot、memory mapper等によって選択された従来のメモリ空間が見える。

`MMU_DATA[00]` は `00h` 固定とし、書込みは無視する。

また、任意のMMU entryに `00h` を設定した場合も同じMSX互換64KB空間へのaliasとして扱う。

```text
MMU_DATA[n] = 00h
    -> logical bank n accesses the MSX-compatible 64KB space
```

`00h` は物理RAM bank 0を意味しない。

---

## 4. MMU変換表

MMUは256 entryの変換表を持つ。

### MMU_DATA

```text
256 x 8bit
```

論理bank番号をindexとして、8bitの物理bank番号を得る。

```text
Logical A23:A16
       |
       v
 MMU_DATA[256 x 8]
       |
       v
 Physical Bank
```

### MMU_ATTR

```text
256 x 8bit
```

各論理bankに対応する属性を保持する。

現仕様で有効な属性は書込み許可 `W` のみとし、その他は予約とする。

---

## 5. MMU実装方式

MMU_DATAおよびMMU_ATTRは、FPGAのLUT/distributed memoryを使用して実装する。

read lookupは完全非同期とする。

```text
Logical Bank
    -> asynchronous MMU lookup
    -> Physical Bank / Attribute
```

MMU lookup自体を理由とする追加T-stateまたはWAITは発生させない。

TLBおよびcacheは設けない。

物理SDRAM等がWAITを必要とする場合は、従来のZ80/T80 WAIT機構を使用する。

---

## 6. MMU I/Oポート

MMU制御には次のI/O portを使用する。

| Port | 名称 | 機能 |
|---|---|---|
| F0h | MMU_INDEX | MMU entry index |
| F1h | MMU_DATA | mapping data |
| F2h | MMU_ATTR | attribute |

I/OはZ80 I/O空間であり、MMU変換対象外である。

---

## 7. MMU_INDEX

`OUT (F0h),A` により現在のMMU indexを設定する。

```text
OUT (F0h),A
    MMU_INDEX <- A
```

MMU_INDEXは8bitである。

---

## 8. MMU_DATAアクセスと自動インクリメント

F1hへのアクセスはMMU_DATAを読み書きし、そのアクセス完了後にMMU_INDEXを自動インクリメントする。

### Write

```text
OUT (F1h),A
    MMU_DATA[MMU_INDEX] <- A
    MMU_INDEX <- MMU_INDEX + 1
```

### Read

```text
IN A,(F1h)
    A <- MMU_DATA[MMU_INDEX]
    MMU_INDEX <- MMU_INDEX + 1
```

incrementは8bit moduloで行う。

```text
FFh + 1 -> 00h
```

ただし `MMU_DATA[00]` は固定00hであり、F1h経由でindex 00hへ書き込んでも内容は変更されない。indexのincrement自体は通常どおり行う。

---

## 9. MMU_ATTRアクセス

F2hは現在のMMU_INDEXに対応する属性を読み書きする。

F2hアクセスではMMU_INDEXを変更しない。

### Write

```text
OUT (F2h),A
    MMU_ATTR[MMU_INDEX] <- A
```

### Read

```text
IN A,(F2h)
    A <- MMU_ATTR[MMU_INDEX]
```

これにより連続設定は、例えば次の形式で行える。

```text
OUT F0,index

loop:
    OUT F2,attr
    OUT F1,data     ; DATA accessでINDEX++
```

---

## 10. MMU書換えの反映タイミング

`OUT (F1h),A` によるMMU_DATA書換えは、そのI/O write完了直後から有効とする。

```text
OUT (F1h),A
    -> MMU_DATA更新
    -> write完了
    -> 次のmemory accessから新mappingを使用
```

TLB/cache等による遅延反映は存在しない。

---

## 11. 自己書換え・実行中領域のremap

実行中コード自身が、そのコードを含む論理領域のMMU mappingを変更する使用方法は禁止する。

ソフトウェアはこれを行ってはならない。

これはソフトウェア規約上の禁止事項とし、CPU/MMUが違反を検出して例外を発生させる機構は設けない。

違反時の動作は保証しない。

---

## 12. MMU_ATTR

MMU_ATTRは8bitだが、現仕様で機能するのはbit 5の `W` のみとする。

```text
bit 7 : RESERVED
bit 6 : RESERVED
bit 5 : W
bit 4 : RESERVED
bit 3 : RESERVED
bit 2 : RESERVED
bit 1 : RESERVED
bit 0 : RESERVED
```

### W

```text
W = 1 : write allowed
W = 0 : write protected
```

予約bitは現在のCPU動作に影響しない。

Read禁止、Execute禁止、VALID判定等は実装しない。

---

## 13. Write protection

MMU_ATTR.Wが0の場合、memory writeを抑止する。

```text
W = 0
    -> physical memory Write Enableをassertしない
    -> memory内容は変化しない
    -> CPU命令は通常どおり完了
    -> exception/trapなし
```

flags等は、その命令本来の仕様に従う。

Readおよびinstruction fetchにはW bitは影響しない。

---

## 14. Reset

Reset時は以下とする。

```text
MMU_INDEX = 00h
MMU_DATA[00..FF] = 00h
MMU_ATTR[00..FF] = 20h
```

したがってreset直後は、すべての論理bankがMSX互換64KB空間へaliasされ、書込み可能である。

```text
logical 00 -> MSX 64KB
logical 01 -> MSX 64KB
...
logical FF -> MSX 64KB
```

M0ではこれらのMMU内容に関係なくMMUをバイパスする。

---

## 15. 物理bank 01h以降

物理bank `01h` 以降の具体的な物理メモリ割当はCPU/MMU仕様では固定しない。

実機のFPGA、SDRAM、BRAM、ROM、VRAM、その他の物理構成に応じて、ユーザまたはOSがMMU_DATAを設定する。

したがって、同じソフトウェア論理bankを異なる実機構成へmappingできる。

CPU/MMUは物理bankの用途を解釈しない。

---

## 16. 存在しない物理メモリへのアクセス

MMU_DATAが実機に存在しない物理bankを指した場合、ハードウェアが未実装領域と判定可能であれば次の動作とする。

```text
Read  -> FFh
Write -> 無視
Exception -> なし
```

Write時はphysical Write Enableをassertしない。

物理アドレスbitを切り捨てることによるwrap/aliasは禁止する。

実機構成や外部device等の理由でCPU/MMU側から有効性を判定できない物理領域については、ユーザ/OSの責任とする。

---

## 17. Byte単位のMMU変換

複数byteのmemory operationでも、各byteアクセスについて独立に論理アドレスを生成しMMU変換を行う。

したがってbank境界を跨ぐアクセスが可能である。

例:

```text
logical 01:FFFF
logical 02:0000
```

が連続した2byteアクセスとなる場合、各logical bankについて個別にMMU_DATAを参照する。

これは以下を含む。

- LD16/LD24
- indexed access
- PUSH24/POP24
- MSP stack access
- CALL.L/RET.L
- CALL.Mx/RET.M
- M2 interrupt frame
- その他の複数byte memory operation

24bitアドレス演算はmodulo 24bitとする。

---

## 18. M2 stackとMMU

M2のactive stack pointerはMSP24である。

通常Z80 PUSH/POPはMSP24をアドレスとして使用するが、転送幅は従来どおり16bitである。

`EX (SP),HL/IX/IY` もM2ではMSP24を使用し、交換対象は下位16bitのレジスタペアのみとする。

```text
EX (SP),HL
    -> address = MSP24
    -> exchange 2 bytes
    -> HL_B unchanged
```

これらは同一segment内での16bit stack操作を想定する。

PUSH24/POP24等の24bit拡張命令は3byteをMSP経由で転送する。

すべてのMSP memory accessはMMU変換対象である。

---

## 19. MMUとRST.L/割り込み

M2のRST.L、CALL.L、interrupt frame等でMSPへアクセスする場合も通常のMMU変換を行う。

RST.Lの飛び先はRST_Bによってbankを指定する。

```text
RST.L xxH -> {RST_B, 00xxh}
```

このPC24からの命令fetchも通常のM2 memory accessとしてMMU変換対象となる。

IRQ/NMIのIVR24/NVR24による飛び先も同様にM2の論理24bitアドレスとして扱う。

---

## 20. MMUによる例外

現仕様ではMMU例外機構を設けない。

- W=0 write: writeを抑止して命令続行。
- 未実装physical bank: 判定可能ならRead=FFh / Write無視。
- reserved attribute: 動作に影響なし。
- 不正なソフトウェアmapping: 原則ユーザ/OS責任。

MMU fault、page fault、protection exception等は実装しない。

---

## 21. 実装規模

MMU table容量は以下となる。

```text
MMU_DATA : 256 x 8 = 2048 bit
MMU_ATTR : 256 x 8 = 2048 bit
Total                 4096 bit
```

これをLUT/distributed memoryとして実装する。

MMUの主な追加論理は、

- asynchronous table lookup
- MMU_INDEX
- F0/F1/F2 I/O decode
- F1 auto increment
- WによるWrite Enable gate
- bank 00/MSX compatible space select
- unmapped physical bank判定（実機側で可能な場合）

である。

---

## 22. 実装・検証順序

MMUは24bit命令群より早い段階で実装・検証する。

推奨順序:

1. M0でMMU bypassを確認。
2. 24bit address generationを実装。
3. 最小M1を実装。
4. MMU_DATA + F0/F1を実装。
5. Tang Nano実機でmapping/alias/bank境界を確認。
6. MMU_ATTR + F2 + W protectionを実装。
7. 未実装physical bank処理を確認。
8. その後LD24、ALU24、M2等を実装。

最初の重要マイルストーンは、

```text
M0 compatible MSX
    +
minimal M1
    +
24bit address generation
    +
MMU_DATA mapping
    +
write protection
```

が実機で安定動作する状態とする。

---

## 23. 主要テスト項目

### Mapping

```text
MMU[01] = physical 01
MMU[02] = physical 02
MMU[03] = physical 03
```

異なる物理bankの固有データが正しく見えること。

### Alias

```text
MMU[01] = 05
MMU[02] = 05
```

両logical bankが同一物理bankを参照すること。

### MSX alias

```text
MMU[n] = 00
```

MSX互換64KB空間が見えること。

### Boundary

```text
01:FFFF -> 02:0000
```

各byteで別々にMMU lookupされること。

### Write protection

```text
W=1 -> write succeeds
W=0 -> memory unchanged
```

CPUはどちらも正常に命令を完了すること。

### Auto increment

```text
INDEX=FE
F1 access -> INDEX=FF
F1 access -> INDEX=00
```

8bit wrapを確認する。

### Mapping update timing

F1 write直後の次memory accessから新mappingが有効であること。

### Invalid physical bank

ハードウェアで未実装と判定可能なbankについて、

```text
Read = FFh
Write = ignored
```

となり、別bankへwrapしないこと。

---

## 24. 確定事項まとめ

- M0はMMU完全bypass。
- M1/M2の24bit memory accessはMMUを使用。
- I/OはMMU対象外。
- bank 00はMSX/Z80互換64KB空間。
- slot/memory mapperを含む従来MSXメモリ空間がbank 00から見える。
- MMU_DATA=00hも同じMSX互換空間へのalias。
- MMU_DATAは256x8bit。
- MMU_ATTRは256x8bit。
- LUT/distributed memoryによる非同期lookup。
- MMU lookupによる追加WAITなし。
- F0=INDEX、F1=DATA、F2=ATTR。
- F1アクセス後にINDEXを自動increment。
- F2アクセスではINDEXを維持。
- F1 write完了直後から新mappingを有効化。
- 実行中コード領域の自己remapは禁止し、ソフトウェア責任。
- MMU_ATTRはbit5 Wのみ有効。他bitは予約。
- W=0はwriteを抑止し、例外なし。
- reset時MMU_DATA=00h、MMU_ATTR=20h。
- 物理bank 01h以降の割当は実機に合わせユーザ/OSが決定。
- 未実装physical bankは判定可能ならRead=FFh、Write無視。
- 物理アドレス切り詰めによるwrapは禁止。
- 複数byte accessはbyte単位でMMU変換。
- M2の既存Z80 16bit絶対memory addressはbank 00として解釈。
