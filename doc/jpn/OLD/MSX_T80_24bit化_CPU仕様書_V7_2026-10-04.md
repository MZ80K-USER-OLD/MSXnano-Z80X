# MSX T80 24bit化 CPU仕様書 V6

## 1. 目的と基本構成

T80系Z80互換CPUを基礎として、MSX互換性を維持しながら24bit論理アドレス空間へ拡張する。

- 論理アドレス: 24bit / 16MB
- メモリ変換: CPU論理24bit → MMU → FPGA物理メモリまたはMSX互換空間
- I/O: Z80互換16bit I/O空間。MMUメモリ変換とは分離
- 実装: マイクロコード化せずT80 decoder/state machine/address generationを拡張
- 24bit算術: 専用24bit ALU
- 新規opcode: 原則 `ED xx` の未使用領域を使用
- IX/IYを自然に選択する命令ではDD/FD prefixを使用可能

## 2. CPUモード

| Mode | PC | データアドレス | Active Stack | 概要 |
|---|---|---|---|---|
| M0 | 16bit | Z80互換16bit | SP16 | MSX/Z80互換 |
| M1 | 16bit | 24bit拡張可 | SP16 | Z80互換実行＋24bitデータ |
| M2 | PC24 | 24bit | MSP24 | 24bit native |

### 2.1 モード設定命令

| Opcode | 命令 | 状態 |
|---|---|---|
| `ED 90` | `SET_M0` | 確定 |
| `ED 91` | `SET_M1` | 確定 |
| `ED 92` | `SET_M2` | 確定 |

旧 `ED 70/71/72` は使用しない。

M2で命令意味上のSPを選択した場合、実体はMSP24を選択する。
M0/M1では従来SP16を選択する。モード変更時にSP16とMSP24をコピーしない。

## 3. 24bitレジスタ

```text
BC24 = {BC_B, BC}
DE24 = {DE_B, DE}
HL24 = {HL_B, HL}
IX24 = {IX_B, IX}
IY24 = {IY_B, IY}
PC24 = {PC_B, PC}
MSP24 = {MSP_B, MSP[15:0]}
```

MSP24は独立した24bit stack pointerで、64KB境界を跨ぐ。

## 4. RESET

拡張レジスタは原則RESET時0とする。

```text
MODE  = M0
BC_B  = 00h
DE_B  = 00h
HL_B  = 00h
IX_B  = 00h
IY_B  = 00h
PC_B  = 00h
MSP24 = 000000h
```

今後追加する特殊レジスタも、特別な理由がなければRESET値0を基本とする。

MMUのRESET仕様はMMU仕様書に従う。

## 5. バンクレジスタ直接アクセス

確定済み:

```text
ED 04  LD BC_B,A
ED 0C  LD A,BC_B
ED 14  LD DE_B,A
ED 1C  LD A,DE_B
ED 24  LD HL_B,A
ED 2C  LD A,HL_B
```

IX_B/IY_Bの直接アクセスは独立した `ED xx` 命令とする。
旧候補 `DD ED 24/2C`, `FD ED 24/2C` は廃止する。
具体的opcodeはED空き領域の最終衝突監査後に確定する。

## 6. IX/IY + d

`d` はsigned 8bit displacement。

### M0

Z80互換16bit加算とし、64KB境界でwrapする。

```text
EA16 = IX16 + sign_extend(d)
EA16 = IY16 + sign_extend(d)
```

IX_B/IY_Bは使用しない。

例:

```text
IX=FFF0h, d=+20h → EA=0010h
```

### M1/M2

IX24/IY24全体へsigned displacementを加算する。

```text
EA24 = IX24 + sign_extend24(d)
EA24 = IY24 + sign_extend24(d)
```

16bit境界ではwrapせずbankへcarry/borrowする。

```text
12:FFF0 + 20h → 13:0010
12:0010 - 20h → 11:FFF0
```

24bit空間全体の端では24bit wrapする。

## 7. 24bit ALU

専用24bit ALUを使用する。

確定している基本命令:
- INC24
- DEC24
- ADD24

フラグ:
- S = result bit23
- Z = 24bit結果全体が0
- H = 保持
- P/V = 24bit signed overflow
- N = ADD/INCで0、SUB/DEC系で1
- C = 24bit carry/borrow。INC24/DEC24では保持

内部のPC/MSP/EAアドレス加算ではFを変更しない。

代表opcode:

```text
ED 23       INC24 HL
DD ED 23    INC24 IX
FD ED 23    INC24 IY

ED 2B       DEC24 HL
DD ED 2B    DEC24 IX
FD ED 2B    DEC24 IY

ED 09       ADD24 HL,BC
DD ED 09    ADD24 IX,BC
FD ED 09    ADD24 IY,BC
```

M2の `ADD24 HL/IX/IY,SP` のSPはMSP24を意味する。

## 8. 24bitロードとレジスタ転送

multi-byteはlittle endianとする。

```text
LOW → HIGH → BANK
```

HL24を24bitレジスタ転送のhubとする方針。

BC/DE/HL/IX/IYおよびMSPとの転送をHL24中心に構成する。
ただし、V5で候補とした `ED A0～A3` はZ80標準ED命令との衝突監査が必要なため、最終opcodeは未確定とする。

## 9. Indexed 16/24bit transfer

DD/FD ED 80～8BをIX/IY indexed pair transferの候補領域とする。

- LD16はdata width 16bit。bank byteは変更しない。
- LD24はLOW/HIGH/BANKの3byte。
- M0のEAは16bit wrap。
- M1/M2のEAは24bitでbank境界を跨ぐ。
- memory accessは各byteごとにMMU変換する。
- Fは変更しない。

## 10. PUSH24 / POP24

対象はZ80のレジスタペアと、その24bit拡張レジスタを基本とする。

確定対象:

```text
BC24
DE24
HL24
IX24
IY24
```

旧命令一覧のZ80 PUSH/POP opcode mirrorを継承し、BC/DE/HLは次を採用する。

```text
ED C1  POP24  BC
ED C5  PUSH24 BC
ED D1  POP24  DE
ED D5  PUSH24 DE
ED E1  POP24  HL
ED E5  PUSH24 HL
```

IX/IYは自然なDD/FD拡張とする。

```text
DD ED E1  POP24  IX
DD ED E5  PUSH24 IX
FD ED E1  POP24  IY
FD ED E5  PUSH24 IY
```

AFは24bit bank byteの定義がないため、PUSH24/POP24対象としては未確定。

### PUSH24 byte order

値 `BB:HHLL`:

```text
MSP-- ; [MSP] = BANK
MSP-- ; [MSP] = HIGH
MSP-- ; [MSP] = LOW
```

完了後:

```text
MSP+0 = LOW
MSP+1 = HIGH
MSP+2 = BANK
```

POP24はLOW→HIGH→BANKの順。
各byteを独立してMMU変換する。

## 11. 24bit制御フロー

確定opcode:

- JR.L: `ED 18/20/28/30/38/C7/D7/E7/F7`
- JP.L: `ED C3` および条件付き `C2/CA/D2/DA/E2/EA/F2/FA`
- CALL.L: `ED CD` および条件付き `C4/CC/D4/DC/E4/EC/F4/FC`
- RET.L: `ED C9` および条件付き `C0/C8/D0/D8/E0/E8/F0/F8`
- RETI.L: `ED 4E`

JR.Lの24bit境界演算詳細は未確定。

## 12. Mode CALL

```text
ED 93 JP.M0
ED 94 JP.M1
ED 95 JP.M2
ED 96 CALL.M0
ED 97 CALL.M1
ED 98 CALL.M2
ED 99 RET.M
```

CALL.MxはMSP24へ4byte frameを保存する。

```text
MSP+0 = PC_L
MSP+1 = PC_H
MSP+2 = PC_B
MSP+3 = MODE
```

RET.Mは逆順に復元する。

## 13. M2割り込み

M2割り込みは有効とする。
「M2では割り込み無効」という案は撤回済み。

M0/M1はZ80/MSX互換IRQ/NMIを維持する。
M2は24bit割り込みvectorを使用する方向とし、IVR24/NVR24、IFF、nest、RETN.L等の詳細は未確定。

## 14. MMUとの接続

詳細は別紙MMU仕様書 V2に従う。

重要事項:

- M0: MMU bypass、MSX互換64KB
- M1/M2: 24bit logical addressのbank byteをMMUへ入力
- `MMU[logical_bank] == 00h` の場合は、logical bank番号に関係なくMSX/Z80互換64KBへ接続
- RESET時はMMU全entryを00hとするため、初期状態では全logical bankがMSX互換64KBのaliasになる
- 複数byteアクセスは各byteを独立してMMU変換する

例:

```text
MMU[05h] = 00h
05:C000 → MSX互換空間 C000h
```

# V7 追補・確定仕様（2026-10-04）

> 本節はV6本文と矛盾する場合、本節を優先する。次回統合版では本文へ吸収する。

## A. 追加確定 opcode

### A.1 bank register

```text
ED 05  LD IX_B,A
ED 0D  LD A,IX_B
ED 15  LD IY_B,A
ED 1D  LD A,IY_B
```

### A.2 HL24 hub / MSP24

```text
ED 06       LD24 HL,BC
ED 0E       LD24 BC,HL
ED 16       LD24 HL,DE
ED 1E       LD24 DE,HL
DD ED 26    LD24 HL,IX
DD ED 2E    LD24 IX,HL
FD ED 26    LD24 HL,IY
FD ED 2E    LD24 IY,HL

ED 34 bl bh bn  LD24 MSP,imm24
ED 35           LD24 MSP,HL
ED 36           LD24 HL,MSP
```

全てfull 24bit転送、source不変、F不変、M0/M1/M2で使用可能。IX/IY↔MSPの専用命令は当面追加せずHL24をhubとして使用する。

既存Z80の `LD SP,HL` / `LD SP,IX` / `LD SP,IY` はレガシーSP16用の互換命令として扱う。M2でMSP24を設定する用途には上記LD24命令を使用する。

### A.3 24bit ALU

```text
ADD24: ED 09/19/29/39
ADC24: ED 07/17/27/37
SBC24: ED 0F/1F/2F/3F
INC24: ED 23
DEC24: ED 2B
CP24 : ED 3D  CP24 HL,DE
```

DD/FD prefixによりHL24 targetをIX24/IY24へ自然拡張する。CP24も `DD ED 3D` = `CP24 IX,DE`, `FD ED 3D` = `CP24 IY,DE`。

CP24は比較のみで結果を書き戻さない。SUB24は追加せず、C=0でSBC24を使用する。AND24/OR24/XOR24および24bit shift/rotateは現時点では追加しない。

ADC24/SBC24/CP24のHは保持。S/Z/PV/Cは24bit演算結果、NはADC24=0、SBC24/CP24=1。

## B. IVR24 / NVR24

```text
ED 9A bl bh bn  LD24 IVR,imm24
ED 9B           LD24 IVR,HL
ED 9C           LD24 HL,IVR
ED 9D bl bh bn  LD24 NVR,imm24
ED 9E           LD24 NVR,HL
ED 9F           LD24 HL,NVR
```

RESET値はIVR24=NVR24=000000h。F不変。M0/M1/M2で設定・参照可能。

## C. SET_M2とPC_B

`SET_M2 = ED 92`。

```text
M0 -> M2 : PC_B <- 00h
M1 -> M2 : PC_B <- 00h
M2 -> M2 : PC_B保持
```

したがってM0/M1からSET_M2した場合はbank 00上の現在の命令ストリームをM2として継続する。別bankへ移行する場合はJP.M2/CALL.M2を使用する。

## D. JR.L bank境界規則

M2ではsigned 16bit displacementを命令完了後のPC24全体へ加算する。

```text
target24 = PC24_after_instruction + sign_extend24(offset16)
```

carry/borrowはPC_Bまで伝播し、24bit全体でwrapする。M0/M1では16bit PC内でwrapする。

## E. Mode control flow operand width

```text
ED 93 al ah       JP.M0 addr16
ED 94 al ah       JP.M1 addr16
ED 95 al ah ab    JP.M2 addr24
ED 96 al ah       CALL.M0 addr16
ED 97 al ah       CALL.M1 addr16
ED 98 al ah ab    CALL.M2 addr24
ED 99             RET.M
```

オペランド幅は「現在MODE」ではなく「遷移先MODE」で決める。M0/M1 targetはbank 00、M2 targetは完全な24bit。

CALL.Mxは呼出元MODEに関係なくMSP24へ4byte frameを保存する。

```text
MSP+0 = return PC_L
MSP+1 = return PC_H
MSP+2 = return PC_B
MSP+3 = return MODE
```

RET.MでPC24とMODEを復元する。

## F. CALL.L / RET.L

CALL.L / RET.LはM2専用の24bit far call/returnとする。

CALL.Lは戻り先PC24をMSPへ3byte保存する。

```text
MSP+0 = PC_L
MSP+1 = PC_H
MSP+2 = PC_B
```

RET.LはMSPから3byteを復元してPC24へ戻す。MODEは保存・変更しない。

M2の通常Z80 `CALL / RET` は同一64KB bank内用のnear call/returnとする。active stackはMSP24だが、戻りアドレスはPC下位16bitの2byteで、PC_Bは変更しない。

## G. PUSH24 / POP24 対象

PUSH24/POP24は24bit化されたレジスタペアに限定する。

```text
BC24 DE24 HL24 IX24 IY24
```

AF/SP/MSP/PC/IVR/NVRは対象外。AF_B/AF24は設けない。

## H. M2割り込み

M0/M1はZ80互換IRQ/NMIを維持する。M2では直接24bit vector方式を使用する。

```text
IRQ -> PC24 = IVR24
NMI -> PC24 = NVR24
```

M2 IRQ受理時はZ80のIFF機構を拡張して使用し、IFF1=0, IFF2=0とする。M2 NMI受理時はIFF2<-IFF1、IFF1<-0。

M2 IRQ/NMIはMSPへ4byte拡張frameを保存する。

```text
MSP+0 = PC_L
MSP+1 = PC_H
MSP+2 = PC_B
MSP+3 = MODE
```

```text
ED 4E  RETI.L
ED 8C  RETN.L
```

RETI.Lは拡張frameからPC24/MODEを復元し、RETI相当の外部割り込み完了処理を行う。RETN.Lは拡張frameを復元後、IFF1<-IFF2を行う。

`ED 8D-8F` は将来の拡張割り込み/例外用に予約する。

## I. RST方針

通常RST（RST 00h～38h）はM0/M1での使用を原則とする。M2では非推奨。

M2用拡張RSTはベクタテーブル方式を採用する方針とする。戻り先PC24をMSPへ3byte保存し、ベクタテーブルから24bit targetを取得する。ベクタテーブル基点レジスタ、opcode、vector番号形式は未確定。

## J. 未定義・未実装 opcode

未定義命令および未実装opcodeはNOPとして処理する。

- レジスタ変更なし
- F変更なし
- trap/exceptionなし
- opcode/prefixとしてフェッチ済みのbyteは消費して次命令へ進む
- 将来予約opcodeも実装されるまではNOP動作
