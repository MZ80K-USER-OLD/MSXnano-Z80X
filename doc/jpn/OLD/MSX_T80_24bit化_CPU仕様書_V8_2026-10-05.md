# MSX T80 24bit化 CPU仕様書 V8

作成年月日: 2026-10-05

## 1. 基本構成

T80系Z80互換CPUを基礎に、MSX互換性を維持しながら24bit論理アドレス空間へ拡張する。論理24bitアドレスはMMUでFPGA物理メモリへ変換する。I/Oは全モードでZ80互換16bit空間。マイクロコード化せずT80
decoder/state machine/address generationを拡張し、24bit算術には専用24bit
ALUを使用する。命令タイミングはZ80/T80を敷衍する。

## 2. MODE

  MODE   PC      Data address   Active stack
  ------ ------- -------------- --------------
  M0     16bit   Z80互換16bit   SP16
  M1     16bit   24bit拡張可    SP16
  M2     PC24    24bit          MSP24

`ED90 SET_M0`, `ED91 SET_M1`, `ED92 SET_M2`。旧ED70/71/72は使用しない。
SET_M2はM0/M1→M2でPC_B=00h、M2→M2ではPC_B保持。

## 3. 拡張レジスタ

`BC24={BC_B,BC}`, `DE24={DE_B,DE}`, `HL24={HL_B,HL}`, `IX24={IX_B,IX}`,
`IY24={IY_B,IY}`, `PC24={PC_B,PC}`, `MSP24={MSP_B,MSP[15:0]}`。
特殊レジスタはIVR24、NVR24、RST_B(8bit)。

RESETはMODE=M0、各bank register/RST_B=00h、MSP24/IVR24/NVR24=000000h。

## 4. Bank register access

``` text
ED04 LD BC_B,A   ED0C LD A,BC_B
ED14 LD DE_B,A   ED1C LD A,DE_B
ED24 LD HL_B,A   ED2C LD A,HL_B
ED05 LD IX_B,A   ED0D LD A,IX_B
ED15 LD IY_B,A   ED1D LD A,IY_B
ED3A LD RST_B,A  ED3E LD A,RST_B
```

F不変、全モード使用可能。

## 5. 24bit address

24bit演算はmodulo 24bit。M0のIX/IY+dは16bit
wrap、M1/M2ではIX24/IY24全体へsigned dを加算しbankへcarry/borrowする。

M2で既存Z80命令が16bit即値メモリアドレスを生成する場合はbank
00と解釈する。bank00はslot/memory
mapperを含むMSX互換64KB。M1/M2のレジスタ間接は対応する24bitレジスタを使用する。

## 6. 24bit ALU

専用24bit ALU。

``` text
ED23 INC24 HL        ED2B DEC24 HL
ED09/19/29/39 ADD24 HL,BC/DE/HL/SP
ED07/17/27/37 ADC24 HL,BC/DE/HL/SP
ED0F/1F/2F/3F SBC24 HL,BC/DE/HL/SP
ED3D CP24 HL,DE
```

DD/FDでHL targetをIX/IYへ置換。M2の新24bit ALU命令でSP operandはMSP24。
S=bit23、Z=24bit zero、H保持、P/V=24bit signed overflow、C=24bit
carry/borrow。SUB24は設けずC=0のSBC24を使う。

## 7. HL24 hub / MSP / vector

``` text
ED06 LD24 HL,BC      ED0E LD24 BC,HL
ED16 LD24 HL,DE      ED1E LD24 DE,HL
DD ED26 LD24 HL,IX   DD ED2E LD24 IX,HL
FD ED26 LD24 HL,IY   FD ED2E LD24 IY,HL
ED34 bl bh bn LD24 MSP,imm24
ED35 LD24 MSP,HL     ED36 LD24 HL,MSP
ED9A bl bh bn LD24 IVR,imm24
ED9B LD24 IVR,HL     ED9C LD24 HL,IVR
ED9D bl bh bn LD24 NVR,imm24
ED9E LD24 NVR,HL     ED9F LD24 HL,NVR
```

full 24bit、source/F不変。既存LD SP,HL/IX/IYはSP16用。

## 8. Indexed pair transfer

DD/FD ED80～8Bを使用。80～82=LD16 BC/DE/HL,(IX/IY+d)、83～85=LD16
store、86～88=LD24 load、89～8B=LD24 store。LD16はbank
byte不変。各byte独立MMU変換。F不変。

## 9. Stack

PUSH24/POP24対象はBC24/DE24/HL24/IX24/IY24のみ。

``` text
ED C1/C5 POP24/PUSH24 BC
ED D1/D5 POP24/PUSH24 DE
ED E1/E5 POP24/PUSH24 HL
DD ED E1/E5 POP24/PUSH24 IX
FD ED E1/E5 POP24/PUSH24 IY
```

3byte、MSP使用、LOW/HIGH/BANK順で復元可能な配置。

M2の通常PUSH/POPはMSPを使うが2byte。`EX (SP),HL/IX/IY`もMSPを使い2byteだけ交換しbank
byteは不変。同一64KB segment内での使用を想定。

## 10. Control flow

JR.L:

``` text
ED18 unconditional
ED20 NZ  ED28 Z  ED30 NC  ED38 C
EDA7 PO  EDAF PE EDB7 P   EDBF M
```

M2ではPC24_after_instruction + sign_extend24(e16)、M0/M1ではPC16。

JP.L=`ED C3`、条件付き`ED C2/CA/D2/DA/E2/EA/F2/FA`。
CALL.L=`ED CD`、条件付き`ED C4/CC/D4/DC/E4/EC/F4/FC`。
RET.L=`ED C9`、条件付き`ED C0/C8/D0/D8/E0/E8/F0/F8`。
CALL.L/RET.LはM2専用でMSPへPC24を3byte保存/復元。M2通常CALL/RETはMSPを使う2byte
near callでPC_B不変。

## 11. Mode control flow

``` text
ED93 al ah       JP.M0
ED94 al ah       JP.M1
ED95 al ah ab    JP.M2
ED96 al ah       CALL.M0
ED97 al ah       CALL.M1
ED98 al ah ab    CALL.M2
ED99             RET.M
```

operand幅は遷移先MODEで決定。CALL.MxはMSPへPC_L,PC_H,PC_B,MODEの4byte
frameを保存しRET.Mで復元。

## 12. RST.L

RST_BはRST.L用8bit bank register。

``` text
EDC7 RST.L 00H  EDCF RST.L 08H
EDD7 RST.L 10H  EDDF RST.L 18H
EDE7 RST.L 20H  EDEF RST.L 28H
EDF7 RST.L 30H  EDFF RST.L 38H
```

M0/M1では対応する通常Z80 RSTとしてSP16へ16bit return
PCをpushし00xxhへ。RST_Bは参照しない。 M2ではreturn PC24をMSPへ3byte
pushし、`PC24={RST_B,00h,RST_vector}`。MODE不変、RET.Lで復帰。

## 13. Interrupt

M0/M1はZ80互換。M2はIRQ→IVR24、NMI→NVR24。IM0/1/2を24bit化しない。 M2
interrupt frameはMSP+0 PC_L,+1 PC_H,+2 PC_B,+3 MODE。 `ED4E RETI.L`,
`ED8C RETN.L`。IRQ受理はIFF1=0,IFF2=0。NMIはIFF2\<-IFF1,IFF1\<-0。RETN.Lは復元後IFF1\<-IFF2。ED8D～8Fは予約。
HALT/WAIT/BUSREQ/BUSACK、DI/EI、interrupt timingはZ80/T80を敷衍する。

## 14. Bank mapping（標準仕様：MMUなし）

M0はbank bypass（既存通り、常にMSX互換64KB）。M1/M2の24bit logical
memory accessはbyte単位の論理バンクバイト（CPUコアが出すA_Bank、A23:A16）が、変換テーブルを介さず**そのまま**物理バンクバイトとして使われる（straight-through
mapping）。I/Oは対象外。

bank00（論理バンク00h、Z80互換空間）は例外的に常に読み書き可能で、既存のMSX互換スロット/BIOS/マッパー経路をそのまま使う（この経路はSD-RAM拡張メモリ経路を通らない）。論理バンク01h以降はそのまま同じ値の物理バンクとしてSD-RAM拡張メモリ領域へ直結される。本標準仕様にはaliasing、per-bank
write protection、MMU_INDEX/MMU_DATA/MMU_ATTR等のI/Oポートは含まれない（すべての非ゼロバンクは常に読み書き可能）。

実装上の注意（MSXnano-Z80X実装例）:
物理bankが指す物理メモリへの経路は、既存のMSX互換メモリ空間（Memory
Mapper/MegaRAM等の既存クライアント）と共有の物理メモリ調停器（arbiter）を通る場合がある。論理アドレスのbyte列はMSX互換16bitアドレスと数値的に重複し得るため、拡張アクセス用のバス要求は既存クライアントの要求より**必ず優先**させること。優先順位を誤ると、拡張メモリへのアクセスが既存クライアント（例:
Memory Mapper RAM）側へ誤って到達し、データ破壊や常時read=00h等の誤動作となる（MSXnano-Z80Xでの実例は[SDRAMメモリマップ.md](SDRAMメモリマップ.md)2.2章参照）。bank00（M0
bypass）はこの経路を使わないため影響を受けない。

### 14.1 オプション機能：MMU（論理→物理バンク変換・write protection）

標準仕様のstraight-through mappingとは別に、論理バンク→物理バンクの変換表と、per-bankのwrite-enable属性を提供するMMU拡張をオプションとして用意している（実装:
[mmu24.vhd](/d:/Users/HeroineFactory/Documents/GIT/MSXNano-Z80X/msxnano-24bit/fpga/G80A/mmu24.vhd)）。本リポジトリに同梱・GHDL検証済みだが、デフォルトビルドの`top.v`からは呼び出されておらず（`MSXNanoTang20K_Z80X24.gprj`上でも`enable="0"`）、合成結果には含まれない。これは、Tang
Nano 20K上の本プロジェクトの現在のFPGA面積配分では、ブートROM等の既存IPが搭載BSRAMを全消費しており、MMUの256エントリテーブルがBSRAMに収まらずLUTベースの distributed
RAMへfallbackしてしまい、論理合成のLUT/Register使用率をそれぞれ約12〜13ポイント押し上げていたためである。BSRAMに空きのある構成や、より大きなFPGAへ移植する場合は、再度有効化することを想定している（再有効化手順は[mmu24.vhd](/d:/Users/HeroineFactory/Documents/GIT/MSXNano-Z80X/msxnano-24bit/fpga/G80A/mmu24.vhd)冒頭のコメント、および`top.v`の該当コメントを参照）。

MMUを有効化した場合の仕様（Phase4/6相当）は以下の通り:

MMUはLUT/distributed
memoryによる非同期lookupで、lookup自体のWAITなし。
F0=MMU_INDEX、F1=MMU_DATA、F2=MMU_ATTR。MMU_INDEXはF0への明示的な書込みによってのみ変更され、F1/F2へのアクセス（読み書きいずれも）による自動incrementは行わない。
MMU_DATA=00hはMSX互換空間へのalias（固定値、書込みは無視）。`OUT(F1),A`完了直後から新mapping有効。実行中コード領域の自己remapは禁止。
ATTRはbit5
Wのみ有効。W=0はWEを出さずwrite無視、例外なし。その他bitは予約。MMU_ATTR[00h]も同様に書込み無視で、Write_Allowは論理バンク00hに対して常に1を返す。
未実装physical
bankをHW判定可能ならread=FFh/write無視。判定不能領域はユーザ/OS責任。物理address切り詰めwrapは禁止。

実装上の注意（MSXnano-Z80X実装例、MMU有効時）:
MMU変換後の物理bankが指す物理メモリへの経路は、既存のMSX互換メモリ空間（Memory
Mapper/MegaRAM等の既存クライアント）と共有の物理メモリ調停器（arbiter）を通る場合がある。論理アドレスのbyte列はMSX互換16bitアドレスと数値的に重複し得るため、拡張アクセス用のバス要求は既存クライアントの要求より**必ず優先**させること。優先順位を誤ると、拡張メモリへのアクセスが既存クライアント（例:
Memory Mapper RAM）側へ誤って到達し、データ破壊や常時read=00h等の誤動作となる（MSXnano-Z80Xでの実例は[SDRAMメモリマップ.md](SDRAMメモリマップ.md)2.2章参照）。bank00（M0 bypass）はこの経路を使わないため影響を受けない。

### 14.2 実装例（MSXnano-Z80X）における物理メモリ配分

本仕様書の論理バンク／物理バンクという概念は実装非依存だが、MSXnano-Z80X実装（Tang
Nano 20K、SD-RAM 8MB＝0x000000〜0x7FFFFF）では、物理バンクバイトは最終的に以下のとおりSD-RAM上の固定アドレスへ写像される。全容は[SDRAMメモリマップ.md](SDRAMメモリマップ.md)を参照のこと（本表はその要約）。

| 用途 | バイトアドレス範囲 | 容量 | 備考 |
|---|---|---|---|
| Memory Mapper（メインRAM） | 0x000000 〜 0x3FFFFF | 4MB | 既存のMSX互換メモリマッパー |
| MegaRAM / SCC拡張RAM | 0x400000 〜 0x5FFFFF | 2MB | 既存のMSX互換カートリッジRAM |
| VDP VRAM（実使用＋予約） | 0x600000 〜 0x63FFFF | 256KB（実使用128KB＋予約128KB） | V9958 VRAM。拡張VRAM構成に備えた予約込み |
| （未使用、予備） | 0x640000 〜 0x64FFFF | 64KB | 物理bank 00h相当の先頭64KB。bank00はこの経路を使わず既存のMSX互換空間を直接参照するため、意図的に未割当 |
| **Z80X24 CPU拡張メモリ**（物理bank 01h〜1Bh、27バンク） | 0x650000 〜 0x7FFFFF | 約1.6875MB | `物理アドレス = 0x640000 + 物理bank×0x10000 + (16bitオフセット)`。物理bank 1Ch以上は本実装では未接続（read=0xFF、write無視） |

標準仕様（MMUなし、本章14章）では、論理バンク＝物理バンクのstraight-through
mappingのため、上表の「物理bank」はそのままCPUコアが出す論理バンクバイト（A_Bank、A23:A16）と一致する。MMUを有効化した構成（14.1章）では、上表の「物理bank」はMMU_DATAテーブルによる変換後の値となる。

## 15. Undefined opcode / timing

未定義・未実装・予約opcodeはNOP。register/F変更、trapなし。fetch済みbyteは消費。
timingはZ80/T80を敷衍し、追加byteには対応するmemory cycleを追加する。
