# MSX T80 24bit化 CPU検討仕様まとめ

更新日: 2026-10-05

## 1. 基本方針

- T80/Z80互換CPUを直接拡張し、マイクロコード方式は採用しない。
- CPU論理アドレスを24bitへ拡張する。
- 24bit論理アドレスとFPGA物理アドレスは分離し、MMUで変換する。
- I/O空間は全モードで従来どおりZ80の16bit I/O空間とする。
- 24bit演算には専用24bit ALUを設ける。
- 命令タイミング、HALT、WAIT、BUSREQ/BUSACK、割り込み受付などの基本動作はZ80/T80を敷衍する。
- 未定義・未実装opcodeはNOPとして扱う。

## 2. 動作モード

### M0 — Z80/MSX互換モード

- PCは16bit。
- active stack pointerは従来のSP16。
- MMUはバイパスする。
- MSX互換64KBメモリ空間を使用する。
- slot、memory mapper等を含む従来MSXメモリ構成を維持する。

### M1 — Z80実行 + 24bitデータアドレス

- PCは16bit。
- コード実行はZ80互換領域。
- active stack pointerはSP16。
- BC/DE/HL、IX/IYのbank byteを利用して24bitデータアドレスを生成できる。
- 24bitデータアクセスではMMUを使用する。

### M2 — 24bit nativeモード

- PC24 = {PC_B, PC[15:0]}。
- active stack pointerはMSP24。
- 24bitデータアドレスおよび24bit制御フローを使用する。
- MMUを使用する。
- 既存Z80命令の即値16bitメモリアドレスはbank 00として解釈する。

例:

```text
LD A,(1234h)  -> 00:1234h
LD (1234h),A  -> 00:1234h
```

- レジスタ間接アドレスは24bit化されたレジスタを使用する。

## 3. モード設定命令

```text
ED 90  SET_M0
ED 91  SET_M1
ED 92  SET_M2
```

旧ED70/71/72は使用しない。

SET_M2時:

- M0/M1 -> M2: PC_B = 00hとして現在のPC16から継続。
- M2 -> M2: PC_Bを保持。

## 4. 24bitレジスタ

```text
BC24 = {BC_B, BC}
DE24 = {DE_B, DE}
HL24 = {HL_B, HL}
IX24 = {IX_B, IX}
IY24 = {IY_B, IY}
PC24 = {PC_B, PC}
MSP24 = {MSP_B, MSP[15:0]}
```

RST.L用に8bit bank registerを追加する。

```text
RST_B
```

Reset時:

- BC_B/DE_B/HL_B/IX_B/IY_B/PC_B/RST_B = 00h
- MSP24 = 000000h
- IVR24 = 000000h
- NVR24 = 000000h
- MODE = M0

## 5. bank register直接アクセス

```text
ED 04  LD BC_B,A
ED 0C  LD A,BC_B
ED 14  LD DE_B,A
ED 1C  LD A,DE_B
ED 24  LD HL_B,A
ED 2C  LD A,HL_B
ED 05  LD IX_B,A
ED 0D  LD A,IX_B
ED 15  LD IY_B,A
ED 1D  LD A,IY_B

ED 3A  LD RST_B,A
ED 3E  LD A,RST_B
```

Fは変更しない。

## 6. MSP24

M2専用active stack pointerとしてMSP24を持つ。SP16とは独立し、モード変更時にも相互コピーしない。

```text
ED 34 bl bh bn  LD24 MSP,imm24
ED 35           LD24 MSP,HL
ED 36           LD24 HL,MSP
```

- immediateはLOW, HIGH, BANK順。
- 全モードから設定・参照可能。
- Fは変更しない。

既存Z80の `LD SP,HL/IX/IY` はSP16操作のままとし、MSP設定命令にはしない。

## 7. HL24 hub転送

```text
ED 06       LD24 HL,BC
ED 0E       LD24 BC,HL
ED 16       LD24 HL,DE
ED 1E       LD24 DE,HL
DD ED 26    LD24 HL,IX
DD ED 2E    LD24 IX,HL
FD ED 26    LD24 HL,IY
FD ED 2E    LD24 IY,HL
```

MSPとの転送はED35/36を使用する。

- 24bit全体を転送。
- sourceは不変。
- Fは不変。
- BC<->DE等の直接転送は設けない。

## 8. IX/IY拡張規則

24bit演算では原則として、HL24命令にDD/FD prefixを追加するとtargetをIX24/IY24へ置換する。

```text
ED xx       -> HL24
DD ED xx    -> IX24
FD ED xx    -> IY24
```

ただしDD/FD ED26/2Eは明示的なHL<->IX/IY転送命令としてdecodeする。

## 9. 24bit ALU

専用24bit ALUを設ける。

### INC24 / DEC24

```text
ED 23       INC24 HL
DD ED 23    INC24 IX
FD ED 23    INC24 IY

ED 2B       DEC24 HL
DD ED 2B    DEC24 IX
FD ED 2B    DEC24 IY
```

### ADD24

```text
ED 09  ADD24 HL,BC
ED 19  ADD24 HL,DE
ED 29  ADD24 HL,HL
ED 39  ADD24 HL,SP
```

DD/FD mirrorを持つ。

新24bit ALU命令でSP operandを指定した場合、M2ではMSP24を意味する。

### ADC24

```text
ED 07  ADC24 HL,BC
ED 17  ADC24 HL,DE
ED 27  ADC24 HL,HL
ED 37  ADC24 HL,SP
```

### SBC24

```text
ED 0F  SBC24 HL,BC
ED 1F  SBC24 HL,DE
ED 2F  SBC24 HL,HL
ED 3F  SBC24 HL,SP
```

### CP24

```text
ED 3D       CP24 HL,DE
DD ED 3D    CP24 IX,DE
FD ED 3D    CP24 IY,DE
```

### Flag方針

ADC/SBC/CP24:

- S = result bit23
- Z = 24bit全体が0
- H = 保持
- P/V = 24bit signed overflow
- N = ADCは0、SBC/CPは1
- C = 24bit carry/borrow

SUB24は設けず、C=0でSBC24を使用する。

## 10. indexed pair load/store

DD/FD ED80-8Bを使用する。

```text
80 LD16 BC,(IX/IY+d)
81 LD16 DE,(IX/IY+d)
82 LD16 HL,(IX/IY+d)
83 LD16 (IX/IY+d),BC
84 LD16 (IX/IY+d),DE
85 LD16 (IX/IY+d),HL
86 LD24 BC,(IX/IY+d)
87 LD24 DE,(IX/IY+d)
88 LD24 HL,(IX/IY+d)
89 LD24 (IX/IY+d),BC
8A LD24 (IX/IY+d),DE
8B LD24 (IX/IY+d),HL
```

- M0: 16bit IX/IY + signed d。16bit wrap。bank byteは無視。
- M1/M2: 24bit IX/IY + sign_extend24(d)。
- LD16ではbank byteを変更しない。
- Fは変更しない。
- 各byteを独立してMMU変換する。

## 11. PUSH24 / POP24

対象は24bit register pairのみ。

- BC24
- DE24
- HL24
- IX24
- IY24

AF/SP/MSP/PC/IVR/NVRは対象外。

```text
ED C1       POP24 BC
ED C5       PUSH24 BC
ED D1       POP24 DE
ED D5       PUSH24 DE
ED E1       POP24 HL
ED E5       PUSH24 HL
DD ED E1    POP24 IX
DD ED E5    PUSH24 IX
FD ED E1    POP24 IY
FD ED E5    PUSH24 IY
```

memory layout:

```text
MSP+0 LOW
MSP+1 HIGH
MSP+2 BANK
```

PUSH24ではBANK, HIGH, LOWの順にMSPをdecrementしながら書く。

MSPは64KB bank境界および24bit wrapを許可する。

## 12. M2での既存Z80 stack命令

M2では既存Z80 PUSH/POPもactive stackとしてMSP24を使用するが、転送幅は従来どおり16bit。

- BC/DE/HL/AF/IX/IYの下位16bitのみ。
- bank byteは変更しない。

### EX (SP),rr

M2ではSPアドレスの代わりにMSP24を使用する。

```text
EX (SP),HL -> EX (MSP24),HL
EX (SP),IX -> EX (MSP24),IX
EX (SP),IY -> EX (MSP24),IY
```

- 交換幅は2byte。
- HL_B/IX_B/IY_Bは変更しない。
- MSP24は変更しない。
- Fは変更しない。
- segment内での使用を想定する。

## 13. 24bit制御フロー

### JR.L

```text
ED 18  JR.L e16
ED 20  JR.L NZ,e16
ED 28  JR.L Z,e16
ED 30  JR.L NC,e16
ED 38  JR.L C,e16
ED A7  JR.L PO,e16
ED AF  JR.L PE,e16
ED B7  JR.L P,e16
ED BF  JR.L M,e16
```

M2ではPC24_after_instruction + sign_extend24(e16)。bank境界を跨ぐ。

M0/M1では16bit PC相対動作。

### JP.L

```text
ED C3  JP.L addr24
```

条件付きはED C2/CA/D2/DA/E2/EA/F2/FA。

### CALL.L / RET.L

M2専用。

```text
ED CD  CALL.L addr24
ED C9  RET.L
```

条件付きCALL.L:

```text
ED C4/CC/D4/DC/E4/EC/F4/FC
```

条件付きRET.L:

```text
ED C0/C8/D0/D8/E0/E8/F0/F8
```

CALL.Lはreturn PC24をMSPへ3byte保存する。MODEは保存しない。

RET.LはPC24を3byte復元する。

## 14. M2通常CALL/RET

M2の既存Z80 CALL/RETは同一64KB bank/segment内用とする。

- stack = MSP24
- return address = PC16のみ2byte
- PC_Bは変更しない

したがって:

```text
CALL/RET      = near 16bit
CALL.L/RET.L  = far 24bit
CALL.Mx/RET.M = mode transition
```

## 15. モード間制御

```text
ED 93  JP.M0 addr16
ED 94  JP.M1 addr16
ED 95  JP.M2 addr24
ED 96  CALL.M0 addr16
ED 97  CALL.M1 addr16
ED 98  CALL.M2 addr24
ED 99  RET.M
```

operand幅はdestination modeで決める。

CALL.MxではMSPへ4byte frameを保存する。

```text
MSP+0 PC_L
MSP+1 PC_H
MSP+2 PC_B
MSP+3 MODE
```

M0/M1からのreturn PC24はbank 00として正規化する。

## 16. IVR24 / NVR24

```text
ED 9A bl bh bn  LD24 IVR,imm24
ED 9B           LD24 IVR,HL
ED 9C           LD24 HL,IVR
ED 9D bl bh bn  LD24 NVR,imm24
ED 9E           LD24 NVR,HL
ED 9F           LD24 HL,NVR
```

- Reset = 000000h
- Fは変更しない。
- 全モードからアクセス可能。

## 17. M2割り込み

M0/M1はZ80互換割り込み。

M2では直接24bit vectorを使用する。

```text
IRQ -> PC24 = IVR24
NMI -> PC24 = NVR24
```

IM0/IM1/IM2を24bit方式へ拡張しない。

interrupt frameはMSPへ4byte保存する。

```text
MSP+0 PC_L
MSP+1 PC_H
MSP+2 PC_B
MSP+3 MODE
```

return命令:

```text
ED 4E  RETI.L
ED 8C  RETN.L
```

RETN.LではZ80のRETNを敷衍してIFF1 <- IFF2を行う。

HALT、WAIT、BUSREQ/BUSACK、DI/EI、IFF、IRQ/NMI優先関係などはZ80/T80を敷衍する。

## 18. RST.L / RST_B

RST用bank registerとして8bitのRST_Bを持つ。

```text
ED 3A  LD RST_B,A
ED 3E  LD A,RST_B
```

RST.L opcodeはZ80 RST opcodeへED prefixを付ける。

```text
ED C7  RST.L 00H
ED CF  RST.L 08H
ED D7  RST.L 10H
ED DF  RST.L 18H
ED E7  RST.L 20H
ED EF  RST.L 28H
ED F7  RST.L 30H
ED FF  RST.L 38H
```

### M0/M1

ED prefix付きRSTは対応する通常Z80 RSTとして動作する。

例:

```text
ED FF -> RST 38H
SP16へreturn PC16をPUSH
PC = 0038h
```

RST_Bは参照しない。

### M2

return PC24をMSPへ3byte保存し、

```text
PC24 = {RST_B, 00h, vector}
```

とする。

例:

```text
ED FF -> PC24 = RST_B:0038h
```

復帰にはRET.Lを使用する。

## 19. MMUから見たCPUアクセス規則

詳細はMMU仕様書を参照する。

CPU側の基本原則:

- M0はMMUを完全バイパス。
- M1/M2の24bit論理メモリアクセスはMMU変換対象。
- bank 00はMSX/Z80互換64KB空間。
- bank 00にはslot/memory mapper等を含むMSXメモリ空間が見える。
- M2の既存Z80即値16bitメモリアドレスはbank 00。
- I/OはMMU対象外。
- MMU lookupは非同期で、MMU自身による追加WAITは発生させない。
- W=0の場合はwrite enableを抑止し、例外は発生させない。
- 存在しない物理bankをハードウェアで判定可能な場合、read=FFh、write=無視。
- 物理アドレス切り詰めによるwrap/aliasは禁止。
- 実行中コード領域のMMU自己remapはソフトウェア規約上禁止する。

## 20. 24bit wrap

24bitアドレス演算はmodulo 2^24とする。

```text
FFFFFFh + 1 -> 000000h
000000h - 1 -> FFFFFFh
```

対象:

- PC24
- MSP24
- JR.L
- indexed effective address
- PUSH24/POP24
- その他24bit address increment/decrement

## 21. 命令タイミング

Z80/T80の既存bus cycle/stateを敷衍する。

- opcode/prefix fetchはZ80 M1規則を維持。
- immediate byteは通常memory read cycle。
- 24bit化で増えるbyte数に応じてmemory cycleを追加。
- WAITは既存T80/Z80方式で挿入。
- MMU lookup自体ではWAITを追加しない。

## 22. 未定義opcode

未定義・予約・未実装opcodeはNOPとして処理する。

- register変更なし。
- F変更なし。
- trap/exceptionなし。
- fetch済みprefix/opcode byteは消費する。

予約例:

```text
ED 8D - ED 8F
```

将来拡張までNOP扱い。

## 23. opcode設計方針

新規opcodeを割り当てる際は以下を避ける。

1. Z80標準ED opcode。
2. undocumented aliasを含む既存動作opcode。
3. 過去の24bit化仕様で使用したopcode。
4. 現行確定opcode。

旧仕様のED70/71/72、ED60-67等は再利用しない。

DD ED / FD ED空間も過去割当を含め衝突監査する。

## 24. 実装上の優先方針

1. M0のZ80/MSX互換性を維持する。
2. 24bit register/address生成を追加する。
3. 最小M1を作る。
4. MMUを早期実装しTang Nano実機で確認する。
5. LD24/24bit ALU/PUSH24等を追加する。
6. M2 PC24/MSP24を実装する。
7. far control flow、mode transition、interruptを追加する。
8. 各段階でGHDL回帰試験と実機合成を行う。

## 25. 現時点で残る確認・実装検証事項

基本アーキテクチャ上の大きな未決事項はかなり解消されている。

実装時に確認する主な項目:

- 各拡張命令の正確なT-state数。
- T80内部state machineへの組込み方法。
- R registerのprefix/M1カウント詳細。
- RETI.Lのdaisy-chain信号タイミング。
- IRQ/NMI nestingの詳細。
- Gowinでの24bit ALU/MMUのFmax。
- 全ED/DD-ED/FD-ED opcodeの最終機械的衝突監査。
- 未実装物理bank判定を各実機構成でどこまでハードウェア化するか。
