# MSXnano T80 24bit拡張 CPU仕様書 V4

**版:** V4\
**作成日:** 2026-10-01\
**対象:** MSXnano / T80ベース Z80互換CPU 24bit拡張\
**状態:**
確定事項を統合。未確定のopcode・詳細動作は明示的に「未定」とする。

## 1. 基本方針

-   T80の既存デコーダ／ステートマシン／アドレス生成を直接拡張する。マイクロコードは使用しない。
-   CPU論理アドレスは24bit（16MB論理空間）。論理24bitアドレスとFPGA物理アドレスは同一視せず、MMUで変換する。
-   メモリアクセスは
    `CPU logical 24bit → MMU → FPGA physical address → SDRAM/BSRAM/MSX slot`
    の経路を取る。
-   I/Oは全モードでZ80互換16bit
    I/O空間を維持し、MMUメモリ変換とは分離する。
-   24bit値は `{BANK[23:16], HIGH[15:8], LOW[7:0]}`。
-   メモリ上の複数byte値はlittle-endianとし、低位アドレスから
    `LOW, HIGH, BANK` とする。
-   24bit算術は専用24bit ALUを使用する。旧仕様の「16bit
    ALUを2サイクル使い回す」方式は採用しない。

## 2. 動作モード

  ---------------------------------------------------------------------------------
  MODE     名称                       実行PC        Active   データアドレス
                                                    Stack    
  -------- -------------------------- ------------- -------- ----------------------
  M0       Z80/MSX互換                `00:PC16`     SP16     bank 00

  M1       Z80互換実行＋24bitデータ   `00:PC16`     SP16     BC/DE/HL/IX/IYのbank
                                                             byteを利用可能

  M2       24bitネイティブ            `PC_B:PC16`   MSP24    24bit
  ---------------------------------------------------------------------------------

### 2.1 SP選択規則

-   M0/M1ではZ80互換SP16を使用する。
-   M2ではSPではなくMSP24が選択される。
-   M0/M1↔M2遷移時にSPとMSPの内容をコピーしない。
-   命令形式上「SP」に対応する24bit自然拡張命令では、M2時はMSP24を対象とする。

## 3. 24bitレジスタ

``` text
BC24 = {BC_B, BC}
DE24 = {DE_B, DE}
HL24 = {HL_B, HL}
IX24 = {IX_B, IX}
IY24 = {IY_B, IY}
PC24 = {PC_B, PC}
MSP24 = {MSP_B, MSP[15:0]}
IVR24 = M2 IRQ Vector Register
NVR24 = M2 NMI Vector Register
```

`MSP_B` は独立したページ選択値ではなく、MSP24のbit23:16そのものである。

## 4. RESET

### 確定

-   RESET後の動作モードはM0。
-   M0の実行PCはbank 00。

### 未定

-   BC_B/DE_B/HL_B/IX_B/IY_B/PC_B/MSP24/IVR24/NVR24の厳密なRESET値は最終確定していない。

## 5. モード制御命令

  Opcode    命令               動作
  --------- ------------------ -------------------------------------
  `ED 90`   `SET_M0`           M0へ切替
  `ED 91`   `SET_M1`           M1へ切替
  `ED 92`   `SET_M2`           M2へ切替
  `ED 93`   `JP.M0 addr16`     MODE=M0、PC=`00:addr16`
  `ED 94`   `JP.M1 addr16`     MODE=M1、PC=`00:addr16`
  `ED 95`   `JP.M2 ext24`      MODE=M2、PC=`ext24`
  `ED 96`   `CALL.M0 addr16`   モード復帰フレームをMSPへ保存しM0へ
  `ED 97`   `CALL.M1 addr16`   モード復帰フレームをMSPへ保存しM1へ
  `ED 98`   `CALL.M2 ext24`    モード復帰フレームをMSPへ保存しM2へ
  `ED 99`   `RET.M`            MSP上のフレームからPC24とMODEを復元

MODE・PC・active stackの切替は命令境界で原子的に成立させる。

### 5.1 SET_M2の未定事項

M0/M1から同一コードストリーム上で `SET_M2` を実行した直後の `PC_B`
を00へ設定するか、保持値を使用するかは未定。`JP.M2` / `CALL.M2`
は明示的なext24を持つためこの曖昧さはない。

## 6. CALL.Mx / RET.M フレーム

CALL.Mxは呼出元MODEに関係なくMSP24を使用する。

PUSH順:

``` text
MODE
PC_B
PC_H
PC_L
```

PUSH完了後の論理配置:

``` text
MSP+0 = PC_L
MSP+1 = PC_H
MSP+2 = PC_B
MSP+3 = MODE
```

RET.Mは `PC_L → PC_H → PC_B → MODE` の順でPOPして復元する。

Return MODE: - `00h` = M0 - `01h` = M1 - `02h` = M2 - その他 =
reserved（異常時動作は未定）

M0/M1からCALL.Mxした場合のReturn PCは `00:xxxx` とする。

## 7. SP / MSP とMSPアクセス命令

MSPはM2のactive
stackであるが、**MSPを設定・読み書きする専用命令はM0/M1/M2すべてで利用可能**とする。

採用する命令形式:

``` text
LD24 MSP,imm24
LD24 HL,MSP
LD24 MSP,HL
```

-   `LD24 HL,MSP`: `HL24 ← MSP24`
-   `LD24 MSP,HL`: `MSP24 ← HL24`
-   Fは変化しない。
-   M0/M1でMSPを書き換えてもactive stackはSP16のまま。
-   M2ではMSP書換えは現在のactive stack pointerそのものの変更となる。
-   opcodeはV4時点で未定。旧 `ED 31 LD XSP,ext24`
    は新しい命名・体系へ整理するため予約候補扱いとする。

## 8. MSPの24bit増減とMMU境界

MSPは24bit全体で増減する。

``` text
12:0000 - 1 = 11:FFFF
12:FFFF + 1 = 13:0000
00:0000 - 1 = FF:FFFF
FF:FFFF + 1 = 00:0000
```

PUSH/POP、CALL.L/RET.L、CALL.Mx/RET.M、M2割り込みフレームの各byteメモリアクセスは、それぞれの論理アドレスについて独立にMMU変換する。したがって64KB境界を越えた物理配置が連続している必要はない。

## 9. PUSH24 / POP24

24bit値 `BB:HHLL` のPUSHはZ80 PUSHの自然な拡張とする。

``` text
MSP-- ; [MSP] = BANK
MSP-- ; [MSP] = HIGH
MSP-- ; [MSP] = LOW
```

PUSH完了後:

``` text
MSP+0 = LOW
MSP+1 = HIGH
MSP+2 = BANK
```

POP24は `LOW → HIGH → BANK`
の順で読み、各byteごとにMSPをインクリメントする。

対象レジスタの最終一覧とopcodeは未定。BC24/DE24/HL24/IX24/IY24を基本候補とする。

## 10. 24bit ALU

24bit演算は専用24bit ALUを使用する。

### 10.1 設計原則

「Z80の16bitペア演算を24bitへ自然に拡張する」。

既存Z80
16bit命令はそのまま残し、24bit版は別命令として追加する。PC24/MSP24は原則として一般ペアALUの自由な宛先にはせず、制御／特殊レジスタとして扱う。

### 10.2 フラグ

  Flag   24bit演算
  ------ -----------------------------------------------
  S      結果bit23
  Z      24bit結果全体が0なら1
  H      **変更しない（保存）**
  P/V    24bit signed overflow
  N      加算/INC系=0、減算/DEC系=1
  C      24bit carry/borrow。INC24/DEC24では変更しない

内部アドレス更新（PC24++, MSP24±1、実効アドレス生成）はFを書き換えない。

例: - `INC24 7FFFFFh → 800000h`: P/V=1 - `DEC24 800000h → 7FFFFFh`:
P/V=1 - `7FFFFFh + 1 → 800000h`: C=0, P/V=1 - `FFFFFFh + 1 → 000000h`:
C=1, P/V=0, Z=1

## 11. BC/DE/HLの24bit自然拡張

既存のZ80 16bitペア命令に対応する形を優先する。

既存割当のうちV4でも継続候補: - `ED 03 INC24 BC` - `ED 13 INC24 DE` -
`ED 23 INC24 HL` - `ED 0B DEC24 BC` - `ED 1B DEC24 DE` -
`ED 2B DEC24 HL` - `ED 09 ADD24 HL,BC` - `ED 19 ADD24 HL,DE` -
`ED 29 ADD24 HL,HL` - `ED 39 ADD24 HL,SP`（M2ではSP指定→MSP24）

ただし、命令名を旧 `XBC/XHL` 表記から `BC24/HL24` または `INC24/ADD24`
形式へ統一する最終表記は未定。

`SUB24`/`CP24`等は「Z80
16bitペア命令の自然拡張」という原則との整合を再確認してから最終採否する。

## 12. IX/IY

IX/IYは独自体系ではなく、**Z80のIX/IY命令を自然に24bitへ拡張する**。

``` text
IX24 = {IX_B,IX}
IY24 = {IY_B,IY}
```

必要な代表形:

``` text
INC24 IX
DEC24 IX
INC24 IY
DEC24 IY

ADD24 IX,BC
ADD24 IX,DE
ADD24 IX,IX
ADD24 IX,SP

ADD24 IY,BC
ADD24 IY,DE
ADD24 IY,IY
ADD24 IY,SP
```

M2の24bit命令でSPが指定された場合はMSP24を選択する。既存Z80の通常
`ADD IX,SP` / `ADD IY,SP` は16bit命令として既存互換動作を維持する。

IX/IY 24bit拡張命令のopcodeはV4時点で未定。DD/FD
prefixを活用しZ80の対応opcodeを自然にmirrorする案を優先検討する。

## 13. 24bitロード

確定した必要機能:

``` text
LD24 HL,imm24
LD24 MSP,imm24
LD24 HL,MSP
LD24 MSP,HL

LD24 IVR,imm24
LD24 HL,IVR
LD24 IVR,HL

LD24 NVR,imm24
LD24 HL,NVR
LD24 NVR,HL
```

メモリとの24bit load/storeはlittle-endianで各byteごとにMMU変換する。

旧割当: - `ED 32 LD XHL,ext24` - `ED 2A LD XHL,(ext24)` -
`ED 22 LD (ext24),XHL`

はV4でも割当候補として保持するが、最終ニーモニックと全ロード命令体系確定時に再確認する。

## 14. M2割り込み

### 14.1 M0/M1

M0/M1のIRQ/NMIはZ80互換を維持し、SP16を使用する。

### 14.2 M2

M2
IRQ/NMIはMSP24を使用する。復帰PCとMODEの保存形式はCALL.Mxと同じExtended
Return Frameを基本とする。

``` text
MSP+0 = PC_L
MSP+1 = PC_H
MSP+2 = PC_B
MSP+3 = MODE
```

M2割り込み受付ではMODEを自動変更せず、M2のままハンドラへ移行する。

### 14.3 ベクタレジスタ

旧 `INT_B:0038h` / `NMI_B:0066h` 方式は採用しない。

``` text
IRQ: PC24 ← IVR24
NMI: PC24 ← NVR24
```

IVR24/NVR24は24bit専用ベクタレジスタとする。M0/M1/M2から設定可能とする。

### 14.4 復帰

-   `RETI.L = ED 4E` は維持。
-   `RETN.L` は必要。
-   RETI.L/RETN.LはExtended Return
    FrameからPC24+MODEを復元する方向とする。
-   IFF1/IFF2、IM状態、RETI
    daisy-chain通知、ネスト割り込みの厳密動作は未定。
-   M2ではZ80
    IM0/IM1/IM2を24bit化せずIVR/NVR方式とする方向。ただしM2のIM状態との関係は最終確定が必要。

### JR.L未定事項

`offset16` は16bit signed displacement。現在の有力仕様は

``` text
PC24 ← (PC24 + sign_extend(offset16)) & FFFFFFh
```

としてbank境界を越える24bit相対分岐とすること。ただしV4では最終確定前のため「未定」とする。旧仕様の「PC_Bを保持して16bit内でwrap」とは一致しない。

## 16. PC fetch

-   M0/M1: PC16を使用し `FFFF→0000`。
-   M2:
    PC24を使用し、命令fetchによるPC増分は24bit全体で行うためbank境界を越えられる。
-   命令fetchの各byteも論理アドレスごとにMMU変換する。

RレジスタのED/DD/FD拡張命令における正確なincrement回数はT80実装確認後に確定する。

## 17. CALL/RETの役割分担

  種類        CALL        RET        Stack                  MODE変更
  ----------- ----------- ---------- ---------------------- ----------
  Z80互換     `CALL`      `RET`      SP16                   なし
  M2内24bit   `CALL.L`    `RET.L`    MSP24                  なし
  モード間    `CALL.Mx`   `RET.M`    MSP24 4byte frame      あり
  M2 IRQ      IRQ entry   `RETI.L`   MSP24 Extended Frame   原則復元
  M2 NMI      NMI entry   `RETN.L`   MSP24 Extended Frame   原則復元

## 18. MMUアクセス原則

以下は複数byteアクセスの各byteごとに論理アドレスを更新し、毎回MMU変換する。

-   24bit load/store
-   PUSH24/POP24
-   CALL.L/RET.L
-   CALL.Mx/RET.M
-   M2 IRQ/NMI frame
-   M2命令fetch

論理bank境界を越えた前後のbyteが物理的に連続することを要求しない。

## 22. IX/IY DD/FD prefix mirror規則（V4追記）

### 確定

IX/IYの24bit拡張は、Z80本来の `DD` / `FD`
prefixによるHL系命令のIX/IY置換を自然に拡張して実装する。

基本規則:

``` text
ED xx        : HL24 / HL_B を対象
DD ED xx     : 対応するHL24 / HL_B対象を IX24 / IX_B へ置換
FD ED xx     : 対応するHL24 / HL_B対象を IY24 / IY_B へ置換
```

この規則により、IX_B/IY_Bの直接アクセス命令を以下の通り確定する。

``` text
ED 24        LD HL_B,A
DD ED 24     LD IX_B,A
FD ED 24     LD IY_B,A

ED 2C        LD A,HL_B
DD ED 2C     LD A,IX_B
FD ED 2C     LD A,IY_B
```

24bit INC/DECも同じmirror規則を使用する。

``` text
ED 23        INC24 HL
DD ED 23     INC24 IX
FD ED 23     INC24 IY

ED 2B        DEC24 HL
DD ED 2B     DEC24 IX
FD ED 2B     DEC24 IY
```

24bit ADDもZ80のHL/IX/IYペア演算の自然な拡張として同じ規則を使用する。

``` text
ED 09        ADD24 HL,BC
DD ED 09     ADD24 IX,BC
FD ED 09     ADD24 IY,BC

ED 19        ADD24 HL,DE
DD ED 19     ADD24 IX,DE
FD ED 19     ADD24 IY,DE

ED 29        ADD24 HL,HL
DD ED 29     ADD24 IX,IX
FD ED 29     ADD24 IY,IY

ED 39        ADD24 HL,SP
DD ED 39     ADD24 IX,SP
FD ED 39     ADD24 IY,SP
```

M2において上記 `SP`
operandが選択された場合、物理的な演算対象はMSP24とする。

``` text
ADD24 HL,SP : HL24 ← HL24 + MSP24
ADD24 IX,SP : IX24 ← IX24 + MSP24
ADD24 IY,SP : IY24 ← IY24 + MSP24
```

通常のZ80 16bit `ADD HL,SP` / `ADD IX,SP` / `ADD IY,SP`
等は既存Z80命令として残し、24bit拡張命令とは区別する。

### デコード原則

`DD ED` / `FD ED`
を独立した新命令空間として無関係な命令へ割り当てるのではなく、可能な限り
`ED` のHL系24bit命令をIX/IYへ置換するprefixとして扱う。

これにより、 - Z80の既存DD/FD prefix思想との整合性を保つ。 - ED
opcode空間の消費を抑える。 -
T80デコーダではHL/IX/IY対象選択を共通化しやすい。 -
HL24/IX24/IY24の24bit ALUデータパスを共通化できる。

なお、旧V4本文中の「IX/IY
24bit拡張命令のopcodeは未定」という記述は、本節で定義した `INC24` /
`DEC24` / `ADD24` および `IX_B/IY_B`
転送については本追記を優先し、これらのopcodeを確定とする。その他のIX/IY拡張命令は引き続き未定とする。

## 23. インデックスアドレッシングによる16bit/24bitレジスタペア転送（V5追加）

### 確定案

`DD ED` をIX系、`FD ED` をIY系として使用し、signed 8bit displacement `d`
を伴うレジスタペア転送を `80h～8Bh` に割り当てる。

  opcode            DD形式             FD形式
  ----------------- ------------------ ------------------
  `DD/FD ED 80 d`   `LD16 BC,(IX+d)`   `LD16 BC,(IY+d)`
  `DD/FD ED 81 d`   `LD16 DE,(IX+d)`   `LD16 DE,(IY+d)`
  `DD/FD ED 82 d`   `LD16 HL,(IX+d)`   `LD16 HL,(IY+d)`
  `DD/FD ED 83 d`   `LD16 (IX+d),BC`   `LD16 (IY+d),BC`
  `DD/FD ED 84 d`   `LD16 (IX+d),DE`   `LD16 (IY+d),DE`
  `DD/FD ED 85 d`   `LD16 (IX+d),HL`   `LD16 (IY+d),HL`
  `DD/FD ED 86 d`   `LD24 BC,(IX+d)`   `LD24 BC,(IY+d)`
  `DD/FD ED 87 d`   `LD24 DE,(IX+d)`   `LD24 DE,(IY+d)`
  `DD/FD ED 88 d`   `LD24 HL,(IX+d)`   `LD24 HL,(IY+d)`
  `DD/FD ED 89 d`   `LD24 (IX+d),BC`   `LD24 (IY+d),BC`
  `DD/FD ED 8A d`   `LD24 (IX+d),DE`   `LD24 (IY+d),DE`
  `DD/FD ED 8B d`   `LD24 (IX+d),HL`   `LD24 (IY+d),HL`

`d` はZ80互換のsigned 8bit displacementとする。

実効アドレスは以下とする。

``` text
M0:
  EA = 00:(IX16 + sign_extend(d))
  EA = 00:(IY16 + sign_extend(d))

M1/M2:
  EA24 = IX24 + sign_extend(d)
  EA24 = IY24 + sign_extend(d)
```

`LD16` と `LD24`
の違いは転送データ幅である。M1/M2では16bit転送でも実効アドレスは24bitで計算する。

``` text
LD16 HL,(IX+d):
  HL_L ← [EA+0]
  HL_H ← [EA+1]
  HL_Bは不変

LD24 HL,(IX+d):
  HL_L ← [EA+0]
  HL_H ← [EA+1]
  HL_B ← [EA+2]
```

storeは逆方向とする。24bitアクセスは64KB境界を越えることができ、各byteアクセスを独立にMMU変換する。これらの転送命令はFを変更しない。

## 24. HL24ハブ型レジスタペア転送（V5追加）

### 確定案

24bitレジスタペア間の直接転送は、命令数増加を抑えるため `HL24`
を転送ハブとする。BC24/DE24/IX24/IY24間の任意の直接転送は設けず、必要な場合はHL24を経由する。

基本転送を `ED A0～A3`、IX/IYとの転送を `DD/FD ED A4～A5` に割り当てる。

``` text
ED A0       LD24 HL,BC    ; HL24 ← BC24
ED A1       LD24 BC,HL    ; BC24 ← HL24
ED A2       LD24 HL,DE    ; HL24 ← DE24
ED A3       LD24 DE,HL    ; DE24 ← HL24

DD ED A4    LD24 IX,HL    ; IX24 ← HL24
DD ED A5    LD24 HL,IX    ; HL24 ← IX24

FD ED A4    LD24 IY,HL    ; IY24 ← HL24
FD ED A5    LD24 HL,IY    ; HL24 ← IY24
```

全命令でsource
registerは不変、24bit全体を転送し、Fは変更しない。M0/M1/M2の全モードで使用可能とする。

この設計により、例えば `BC24 → IX24` は次の2命令で実現する。

``` text
LD24 HL,BC
LD24 IX,HL
```

特殊24bitレジスタであるMSP/IVR/NVRについても、既定方針どおりHL24を転送ハブとして扱う。

## 25. V5追加opcode領域

今回追加する領域は以下とする。

``` text
DD/FD ED 80～8B : IX/IY indexed 16/24bit pair load/store
ED A0～A3       : BC/DE ↔ HL 24bit transfer
DD/FD ED A4～A5 : IX/IY ↔ HL 24bit transfer
```

V4で確定済みの `DD/FD ED 09,19,23,24,29,2B,2C,39` 等とは重複しない。
