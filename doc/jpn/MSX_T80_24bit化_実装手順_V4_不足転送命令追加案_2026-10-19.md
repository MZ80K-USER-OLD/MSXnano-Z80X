## 1. 実装方針

実装は、Z80/T80互換性を維持しながら段階的に24bit化する。

基本順序は次のとおり。

**M0互換維持 → 24bitレジスタ/アドレス生成 → 最小M1 → MMU早期実装・実機検証 → 24bit命令群 → M2 → 割り込み/周辺動作**

特にMMUは後回しにせず、24bit命令群を本格実装する前に実機動作を確認する。

命令タイミングは、原則としてZ80/T80の既存タイミング仕様を敷衍する。24bit化で追加されるオペランドbyteやメモリアクセスについて、既存のZ80メモリサイクルを拡張して構成する。

## 2. Phase 0 — 現行T80/MSXnano基準化

- 変更前のT80/MSXnanoを基準版として固定する。
- M0ではMMUを完全にバイパスする。
- Z80互換の16bit PC/SPを使用する。
- MSX BIOS、RAM/ROM、I/O、割り込み、既存ソフトの動作を確認する。

**完了条件:** 24bit拡張前のMSX互換動作が再現可能。

## 3. Phase 1 — 24bitレジスタ基盤

追加: `BC_B`, `DE_B`, `HL_B`, `IX_B`, `IY_B`, `PC_B`, `MSP24`。

```text
BC24 = {BC_B, BC}
DE24 = {DE_B, DE}
HL24 = {HL_B, HL}
IX24 = {IX_B, IX}
IY24 = {IY_B, IY}
PC24 = {PC_B, PC}
```

Resetは各bank register=00h、MSP24=000000h、MODE=M0。

## 4. Phase 2 — 24bitアドレス生成

24bitアドレス生成器を追加する。`+1`, `-1`, signed displacement、16bit displacementを24bit moduloで処理する。

```text
FFFFFF + 1 = 000000
000000 - 1 = FFFFFF
```

64KB bank境界carry/borrow、IX/IY displacement、MSP increment/decrementを検証する。

## 5. Phase 3 — 最小M1

全24bit命令を待たず、MMU検証に必要な最小限の24bitデータアクセスを実装する。

- PCは16bit。
- データアドレスのみ24bit化。
- HL24等から24bit論理アドレスを生成。

## 6. Phase 4 — MMU_DATA実装

MMU変換表は **LUT/distributed memory** で実装し、非同期lookupとする。

```text
logical A23:A16
       |
       v
 MMU_DATA[256 x 8]
       |
       v
 physical bank
```

MMU lookupそのものによる追加WAIT/T-stateは発生させない。

```text
F0h : MMU_INDEX
F1h : MMU_DATA
F2h : MMU_ATTR
```

まずF0/F1を実装する。Reset時は全MMU_DATA=00h。MMU_DATA[00]=00h固定。値00hはMSX互換64KBへのaliasとし、bank00への書込みは無視する。

## 7. Phase 5 — MMU実機検証

最初の重要マイルストーン。

物理bankへ固有パターンを置き、mapping変更でCPUから見える値が変わることを確認する。

```text
physical bank 01 -> 11h
physical bank 02 -> 22h
physical bank 03 -> 33h
```

Alias試験:

```text
MMU[01] = 05h
MMU[02] = 05h
```

logical bank 01/02が同一物理bankを参照することを確認する。またMMU[n]=00hが同一MSX互換64KBを指すことを確認する。

Bank境界試験:

```text
00:FFFF -> 01:0000
01:FFFF -> 02:0000
```

各byteアクセスごとにMMU lookupされることを確認する。

## 8. Phase 6 — MMU_ATTR.W

現行実装では書込み許可bitだけを有効にする。

```text
MMU_ATTR bit5 = W
W=1 : 書込み許可
W=0 : 書込み禁止
bit7,6,4,3,2,1,0 = RESERVED
```

W=0ではWrite Enableを出さず、実メモリを変更しない。CPU命令は正常完了し、例外/trapは発生させない。Reset値は20hとする。

## 9. Phase 7 — LD24系命令

- bank register直接LD
- HL24 hub転送
- MSP24設定/取得
- IVR24/NVR24
- indexed LD16/LD24

24bit little endian。各byteアクセスは独立してMMU変換する。

## 10. Phase 8 — 24bit ALU

実装対象: `INC24`, `DEC24`, `ADD24`, `ADC24`, `SBC24`, `CP24`。

専用24bit ALUを使用し、carry/borrow、signed overflow、bank境界、各flagを検証する。

## 11. Phase 9 — PUSH24 / POP24

対象はBC24/DE24/HL24/IX24/IY24。AFは対象外。MSP24を使用し3byte転送する。

```text
MSP+0 = LOW
MSP+1 = HIGH
MSP+2 = BANK
```

bank境界、24bit wrap、byte単位MMU変換を検証する。

## 12. Phase 10 — M2基本動作

- PC24命令fetch。
- MSP24をactive stack pointerとする。
- SET_M2。
- M2での通常Z80 PUSH/POPはMSPを使用し2byte転送。

M0/M1からSET_M2時は `PC_B <- 00h`。M2→M2ではPC_B保持。

## 13. Phase 11 — M2制御フロー

通常CALL/RETは同一64KB segment内用。

```text
CALL/RET
stack = MSP
return address = 16bit
PC_B = 不変
```

CALL.L/RET.LはM2専用24bit far call。CALL.Lは戻りPC24をMSPへ3byte保存し、RET.Lは3byte復元する。

JR.LはM2ではPC24全体にsigned 16bit displacementを加算しbank境界を跨ぐ。

## 14. Phase 12 — モード間制御

```text
ED 93 JP.M0 addr16
ED 94 JP.M1 addr16
ED 95 JP.M2 addr24
ED 96 CALL.M0 addr16
ED 97 CALL.M1 addr16
ED 98 CALL.M2 addr24
ED 99 RET.M
```

CALL.MxはMSPへ4byte保存する。

```text
MSP+0 = PC_L
MSP+1 = PC_H
MSP+2 = PC_B
MSP+3 = MODE
```

## 15. Phase 13 — M2割り込み

- IRQ -> IVR24
- NMI -> NVR24
- M2ではIM0/IM1/IM2を24bit化せず直接24bit vectorを使用。

Extended interrupt frame:

```text
MSP+0 = PC_L
MSP+1 = PC_H
MSP+2 = PC_B
MSP+3 = MODE
```

Returnは `RETI.L = ED 4E`, `RETN.L = ED 8C`。IFFはZ80のIFF機構を拡張して使用する。

## 16. Phase 14 — RST.L

M2用拡張RSTはベクタ方式とする。

未確定:
- vector table base register
- RVR24新設の可否
- vector数
- opcode
- table layout詳細

通常Z80 RSTはM0/M1での使用を原則とし、M2では非推奨。

## 17. Phase 15 — 周辺CPU動作

- HALT
- WAIT
- BUSREQ/BUSACK
- R register
- IRQ/NMI受付タイミング
- prefix fetch
- refresh動作

原則として既存Z80/T80の動作を維持・敷衍する。

## 18. Phase 16 — 総合検証

M0: MSX互換性、MMU bypass、Z80命令回帰。

M1: 16bit code + 24bit data、MMU mapping、bank境界アクセス。

M2: PC24、MSP24、near/far call、24bit ALU、PUSH24/POP24、interrupt。

MMU: alias、mapping変更、W protect、bank boundary、M0 bypass。

## 19. 推奨マイルストーン

- **Milestone A:** M0互換MSX
- **Milestone B:** 最小M1 + MMUをTang Nano実機で確認
- **Milestone C:** MMU write protectionまで確認し安定版保存
- **Milestone D:** LD24/ALU24/PUSH24/POP24
- **Milestone E:** M2 PC24 + MSP24 + 24bit control flow
- **Milestone F:** IVR/NVR、RETI.L/RETN.L、CALL.Mx/RET.M
- **Milestone G:** M0/M1/M2総合統合

## 20. 実装上の基本原則

1. M0互換性を常に回帰試験する。
2. 一度に複数機能を追加しない。
3. MMUは24bit命令群より早期に実機検証する。
4. MMU lookupはLUT/distributed memoryによる非同期readとし、MMU自身によるWAITを発生させない。
5. 24bit memory operationはbyte単位でMMU変換する。
6. 命令タイミングはZ80/T80の既存仕様を敷衍する。
7. 未定義/未実装opcodeはNOPとして処理する。
8. 各Phase完了時にGHDL回帰試験を実行する。
9. Milestone単位で実機確認済みrevisionを保存する。


## 21. 2026-10-11差分実装手順（V4）

### 21.1 標準構成とオプションMMU

1. 標準構成で `MMU_ENABLE=0` とし、M0は既存MSX互換経路、M1/M2は24bit logical bankを物理bankへstraight-through出力する。bank00は従来MSX互換経路を維持する。
2. MSXnano-Z80X実装では添付CPU仕様書V8の物理メモリ割当（SDRAM `0x640000 + bank*0x10000 + offset`、bank01h～1Bh）を照合する。拡張メモリ要求がMemory Mapper等の既存クライアントへ誤配送されないようarbiterの優先順位を検証する。
3. `MMU_ENABLE=1` はオプションの独立ビルドで検証する。F0=INDEX、F1=DATA、F2=ATTR。INDEXはF0明示書込みでのみ更新し、F1/F2の読み書きでは保持する。bank00のDATA/ATTR書込みは無視し、bank00書込み許可は常時1。
4. 両構成でLUT/FF/BSRAM/Fmaxを記録する。添付V8の資源増加値は履歴値であり、再合成値として扱わない。

### 21.2 LEA.L追加、PEA.L不採用

1. `DD ED 68 d` / `FD ED 68 d` → `LEA.L HL,(IX/IY+d)`。
2. `DD ED 69 d` / `FD ED 69 d` → `LEA.L DE,(IX/IY+d)`。
3. 共有EA生成器で `IX/IY + sign_extend(d)` を計算し、HL24/DE24の全24bitへロード。M0では16bit wrap＋bank00、M1/M2では24bit wrap。F、IX/IY、SP/MSP不変、実効アドレスのメモリアクセスなし。
4. `DD/FD ED 6A d` はPEAとしてデコードしない。未定義命令としてのprefix/変位消費サイクルはRTL監査で確定する。
5. `xx:FFFF + 1`、`xx:0000 - 1`、`FFFFFF+1`、d=-128/+127、HL/DE bank更新、フラグ保持をGHDLで確認する。

### 21.3 M2割り込み

1. IM0/1/2に依存せずIRQ→IVR24、NMI→NVR24とする。M0/M1の既存Z80互換割り込み経路は維持する。
2. M2受付時MSP24を4減算し、最終スタック像を `[MSP+0]=PC_L, +1=PC_H, +2=PC_B, +3=MODE` とする。各バイトのbank跨ぎを検証する。
3. `RETI.L`（ED4E）/`RETN.L`（ED8C）で4バイト復帰する。通常RETI/RETNのM2時動作とSET_Mx境界受付は未確定のため、確定まで個別テスト項目とする。

### 21.4 検証順序

`MMU無効でM0回帰 → M1のEA24 → LEA.L → M2のPC24/MSP24 → IRQ/NMI 4byte → MMU有効の別ビルド → 実機SDRAM/arbiter → 資源とFmax`。


### 21.5 IX/IY間接の16bit・24bitペア転送（既存仕様の実装・検証明確化）

CPU仕様書V10第8章で**定義済み**の命令を実装対象として明記する。新規opcodeの割当ではない。`DD`はIX24、`FD`はIY24を基準とし、`d`は符号付き8bit変位。全命令は4byte（prefix、ED、opcode、d）。

| opcode（IX版） | opcode（IY版） | 命令 | 転送 |
|---|---|---|---|
| DD ED 80 d | FD ED 80 d | LD16 BC,(IX/IY+d) | 2byte read |
| DD ED 81 d | FD ED 81 d | LD16 DE,(IX/IY+d) | 2byte read |
| DD ED 82 d | FD ED 82 d | LD16 HL,(IX/IY+d) | 2byte read |
| DD ED 83 d | FD ED 83 d | LD16 (IX/IY+d),BC | 2byte write |
| DD ED 84 d | FD ED 84 d | LD16 (IX/IY+d),DE | 2byte write |
| DD ED 85 d | FD ED 85 d | LD16 (IX/IY+d),HL | 2byte write |
| DD ED 86 d | FD ED 86 d | LD24 BC,(IX/IY+d) | 3byte read |
| DD ED 87 d | FD ED 87 d | LD24 DE,(IX/IY+d) | 3byte read |
| DD ED 88 d | FD ED 88 d | LD24 HL,(IX/IY+d) | 3byte read |
| DD ED 89 d | FD ED 89 d | LD24 (IX/IY+d),BC | 3byte write |
| DD ED 8A d | FD ED 8A d | LD24 (IX/IY+d),DE | 3byte write |
| DD ED 8B d | FD ED 8B d | LD24 (IX/IY+d),HL | 3byte write |

1. 共有EA24生成器で`IX24/IY24 + sign_extend(d)`を計算する。M0は16bit wrap＋bank00、M1/M2は24bit wrap（CPU仕様書V10第5章）。
2. 16bit転送はLOW/HIGHの2byteのみ。load時のBC_B/DE_B/HL_Bは不変、store時もbank byteは書き込まない。24bit転送はLOW/HIGH/BANKの3byte。各アクセスでEA24を+1し、bank境界を跨ぐ。
3. F、アドレス元IX/IYは不変。WAIT/SDRAM調停中はアドレス・write data・読み込み先の取り込みを安定させ、1byteにつき1回だけコミットする。既存T80のprefix処理とM0互換動作を回帰する。
4. GHDLで24種類（DD/FD × 12）を網羅し、通常、`01:FFFE`跨ぎ、`FFFFFF` wrap、`d=-128/+127`、16bit転送時bank保持、F保持、WAIT挿入、連続アクセス、M0/M1/M2を検証する。実機ではSDRAM arbiter競合時も確認する。
5. 命令が仕様書に存在することと、RTLに実装済み・実機確認済みであることは区別する。各opcodeのdecoder/state machine/byte転送経路を監査して進捗を記録する。

### 21.6 ED単独prefixの追加メモリロード命令（別提案・未実装）

別紙「24bitメモリロード追加命令案」にある`ED 00 = LD24 BC,(HL)`、`ED 01 = LD24 DE,(HL)`、`ED 02 al ah ab = LD24 HL,(addr24)`は、上記IX/IY間接転送とは**別の新規提案**であり、CPU仕様書V10の確定命令には含まれない。opcode衝突、M0動作、RTLデコード・WAIT・bank跨ぎを審査し、採用決定後に別途実装する。現時点で完了扱いにしない。


## 2026-10-19 追加追補：ED単独プレフィックスの不足転送命令（設計案）

本追補は**命令割当の提案**であり、RTL実装済み・実機確認済みではない。正式仕様に採用する前にRTLデコーダ、標準Z80互換性、全prefixの衝突監査を行う。元のPhase番号は変更しない。

| opcode | 命令 | opcode | 命令 |
|---|---|---|---|
| `ED 03` | `LD24 (HL),BC` | `ED 08` | `LD24 (HL),DE` |
| `ED 0A` | `LD16 BC,(HL)` | `ED 0B` | `LD16 DE,(HL)` |
| `ED 10` | `LD16 (HL),BC` | `ED 11` | `LD16 (HL),DE` |
| `ED 12` | `LD24 BC,(addr24)` | `ED 13` | `LD24 DE,(addr24)` |
| `ED 1A` | `LD24 (addr24),BC` | `ED 1B` | `LD24 (addr24),DE` |
| `ED 21` | `LD24 (addr24),HL` | `ED 22` | `LD24 BC,imm24` |
| `ED 25` | `LD24 DE,imm24` | `ED 26` | `LD24 HL,imm24` |
| `ED 2D` | `LD24 IX,imm24` | `ED 2E` | `LD24 IY,imm24` |
| `ED 32` | `LD24 BC,DE` | `ED 33` | `LD24 DE,BC` |

既存の追加案：`ED 00 LD24 BC,(HL)`、`ED 01 LD24 DE,(HL)`、`ED 02 LD24 HL,(addr24)`は継続。`ED 03/08`はHL24間接3バイト書込。`ED 0A/0B/10/11`はHL24間接2バイト転送（宛先bankバイト保持）。絶対アドレス形式と即値形式はオペランド3バイトをLOW→HIGH→BANK順に格納する。3バイトメモリ転送もLOW→HIGH→BANK順、2バイトはLOW→HIGH順。アドレスは各バイトで24bit moduloインクリメントし、64KBバンク境界をまたぐ。全命令F不変、HL間接のアドレス元HL24不変、store時のsrcレジスタ不変。M0動作は未確定（M1/M2使用を暫定条件）。

### 実装・検証への追加条件

- Phase 7（LD24系）：24bit即値BC/DE/HL/IX/IY、BC↔DE、絶対アドレスload/store、HL間接load/storeを新規提案としてデコード・レジスタ書込み経路へ追加。

- 実機：SDRAM調停とWAIT/CENの影響を確認。POP24障害と共通の連続read経路の切り分けにも使用。
- **注意**：`ED 22/25/26/2D/2E`等の採用は今回の命令表に対する衝突監査に限る。外部拡張・未掲載RTLデコードとの完全非衝突は未確認。
