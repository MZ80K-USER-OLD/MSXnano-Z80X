# MSX T80 24bit化 実装手順

更新日: 2026-10-05

## 1. 実装方針

実装は、Z80/T80互換性を維持しながら段階的に24bit化する。

基本順序は次のとおり。

**M0互換維持 → 24bitレジスタ/アドレス生成 → 最小M1 → MMU早期実装・実機検証 → 24bit命令群 → M2 → 割り込み/周辺動作**

特にMMUは後回しにせず、24bit命令群を本格実装する前に実機動作を確認する。

命令タイミングは、原則としてZ80/T80の既存タイミング仕様を敷衍する。24bit化で追加されるオペランドbyteやメモリアクセスについて、既存のZ80メモリサイクルを拡張して構成する。

## 2. Phase 0 — 現行T80/MSXnano基準化

- 変更前のT80/MSXnanoを基準版として固定する。
- M0ではMMUを完全にバイパスする。
- Z80互換の16bit PC/SPを使用する。
- MSX BIOS、RAM/ROM、I/O、割り込み、既存ソフトの動作を確認する。

**完了条件:** 24bit拡張前のMSX互換動作が再現可能。

## 3. Phase 1 — 24bitレジスタ基盤

追加: `BC_B`, `DE_B`, `HL_B`, `IX_B`, `IY_B`, `PC_B`, `MSP24`。

```text
BC24 = {BC_B, BC}
DE24 = {DE_B, DE}
HL24 = {HL_B, HL}
IX24 = {IX_B, IX}
IY24 = {IY_B, IY}
PC24 = {PC_B, PC}
```

Resetは各bank register=00h、MSP24=000000h、MODE=M0。

## 4. Phase 2 — 24bitアドレス生成

24bitアドレス生成器を追加する。`+1`, `-1`, signed displacement、16bit displacementを24bit moduloで処理する。

```text
FFFFFF + 1 = 000000
000000 - 1 = FFFFFF
```

64KB bank境界carry/borrow、IX/IY displacement、MSP increment/decrementを検証する。

## 5. Phase 3 — 最小M1

全24bit命令を待たず、MMU検証に必要な最小限の24bitデータアクセスを実装する。

- PCは16bit。
- データアドレスのみ24bit化。
- HL24等から24bit論理アドレスを生成。

## 6. Phase 4 — MMU_DATA実装

MMU変換表は **LUT/distributed memory** で実装し、非同期lookupとする。

```text
logical A23:A16
       |
       v
 MMU_DATA[256 x 8]
       |
       v
 physical bank
```

MMU lookupそのものによる追加WAIT/T-stateは発生させない。

```text
F0h : MMU_INDEX
F1h : MMU_DATA
F2h : MMU_ATTR
```

まずF0/F1を実装する。Reset時は全MMU_DATA=00h。MMU_DATA[00]=00h固定。値00hはMSX互換64KBへのaliasとし、bank00への書込みは無視する。

## 7. Phase 5 — MMU実機検証

最初の重要マイルストーン。

物理bankへ固有パターンを置き、mapping変更でCPUから見える値が変わることを確認する。

```text
physical bank 01 -> 11h
physical bank 02 -> 22h
physical bank 03 -> 33h
```

Alias試験:

```text
MMU[01] = 05h
MMU[02] = 05h
```

logical bank 01/02が同一物理bankを参照することを確認する。またMMU[n]=00hが同一MSX互換64KBを指すことを確認する。

Bank境界試験:

```text
00:FFFF -> 01:0000
01:FFFF -> 02:0000
```

各byteアクセスごとにMMU lookupされることを確認する。

## 8. Phase 6 — MMU_ATTR.W

現行実装では書込み許可bitだけを有効にする。

```text
MMU_ATTR bit5 = W
W=1 : 書込み許可
W=0 : 書込み禁止
bit7,6,4,3,2,1,0 = RESERVED
```

W=0ではWrite Enableを出さず、実メモリを変更しない。CPU命令は正常完了し、例外/trapは発生させない。Reset値は20hとする。

## 9. Phase 7 — LD24系命令

- bank register直接LD
- HL24 hub転送
- MSP24設定/取得
- IVR24/NVR24
- indexed LD16/LD24

24bit little endian。各byteアクセスは独立してMMU変換する。

## 10. Phase 8 — 24bit ALU

実装対象: `INC24`, `DEC24`, `ADD24`, `ADC24`, `SBC24`, `CP24`。

専用24bit ALUを使用し、carry/borrow、signed overflow、bank境界、各flagを検証する。

## 11. Phase 9 — PUSH24 / POP24

対象はBC24/DE24/HL24/IX24/IY24。AFは対象外。MSP24を使用し3byte転送する。

```text
MSP+0 = LOW
MSP+1 = HIGH
MSP+2 = BANK
```

bank境界、24bit wrap、byte単位MMU変換を検証する。

## 12. Phase 10 — M2基本動作

- PC24命令fetch。
- MSP24をactive stack pointerとする。
- SET_M2。
- M2での通常Z80 PUSH/POPはMSPを使用し2byte転送。

M0/M1からSET_M2時は `PC_B <- 00h`。M2→M2ではPC_B保持。

## 13. Phase 11 — M2制御フロー

通常CALL/RETは同一64KB segment内用。

```text
CALL/RET
stack = MSP
return address = 16bit
PC_B = 不変
```

CALL.L/RET.LはM2専用24bit far call。CALL.Lは戻りPC24をMSPへ3byte保存し、RET.Lは3byte復元する。

JR.LはM2ではPC24全体にsigned 16bit displacementを加算しbank境界を跨ぐ。

## 14. Phase 12 — モード間制御

```text
ED 93 JP.M0 addr16
ED 94 JP.M1 addr16
ED 95 JP.M2 addr24
ED 96 CALL.M0 addr16
ED 97 CALL.M1 addr16
ED 98 CALL.M2 addr24
ED 99 RET.M
```

CALL.MxはMSPへ4byte保存する。

```text
MSP+0 = PC_L
MSP+1 = PC_H
MSP+2 = PC_B
MSP+3 = MODE
```

## 15. Phase 13 — M2割り込み

- IRQ -> IVR24
- NMI -> NVR24
- M2ではIM0/IM1/IM2を24bit化せず直接24bit vectorを使用。

Extended interrupt frame:

```text
MSP+0 = PC_L
MSP+1 = PC_H
MSP+2 = PC_B
MSP+3 = MODE
```

Returnは `RETI.L = ED 4E`, `RETN.L = ED 8C`。IFFはZ80のIFF機構を拡張して使用する。

## 16. Phase 14 — RST.L

M2用拡張RSTはベクタ方式とする。

未確定:
- vector table base register
- RVR24新設の可否
- vector数
- opcode
- table layout詳細

通常Z80 RSTはM0/M1での使用を原則とし、M2では非推奨。

## 17. Phase 15 — 周辺CPU動作

- HALT
- WAIT
- BUSREQ/BUSACK
- R register
- IRQ/NMI受付タイミング
- prefix fetch
- refresh動作

原則として既存Z80/T80の動作を維持・敷衍する。

## 18. Phase 16 — 総合検証

M0: MSX互換性、MMU bypass、Z80命令回帰。

M1: 16bit code + 24bit data、MMU mapping、bank境界アクセス。

M2: PC24、MSP24、near/far call、24bit ALU、PUSH24/POP24、interrupt。

MMU: alias、mapping変更、W protect、bank boundary、M0 bypass。

## 19. 推奨マイルストーン

- **Milestone A:** M0互換MSX
- **Milestone B:** 最小M1 + MMUをTang Nano実機で確認
- **Milestone C:** MMU write protectionまで確認し安定版保存
- **Milestone D:** LD24/ALU24/PUSH24/POP24
- **Milestone E:** M2 PC24 + MSP24 + 24bit control flow
- **Milestone F:** IVR/NVR、RETI.L/RETN.L、CALL.Mx/RET.M
- **Milestone G:** M0/M1/M2総合統合

## 20. 実装上の基本原則

1. M0互換性を常に回帰試験する。
2. 一度に複数機能を追加しない。
3. MMUは24bit命令群より早期に実機検証する。
4. MMU lookupはLUT/distributed memoryによる非同期readとし、MMU自身によるWAITを発生させない。
5. 24bit memory operationはbyte単位でMMU変換する。
6. 命令タイミングはZ80/T80の既存仕様を敷衍する。
7. 未定義/未実装opcodeはNOPとして処理する。
8. 各Phase完了時にGHDL回帰試験を実行する。
9. Milestone単位で実機確認済みrevisionを保存する。
