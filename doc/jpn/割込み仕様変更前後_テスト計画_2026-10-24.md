# 割込み仕様変更前後のテスト計画

作成日: 2026-10-24

## 目的と進め方

SDRAM要求受理修正後の安定点を確定してから、共通割込みバンクIBR・
M2のIM2対応・SYSCALLの仕様変更へ進む。
不具合修正の回帰確認と新仕様の検証を混同しない。
旧仕様の網羅試験を新たに増やすのではなく、既存の短い実機回帰を先に終える。
テスト全体は作り直さず、変更対象の判定を改訂し、無関係な試験は維持する。

## 1. 現在の確認済み事項

- バス分離修正後、P24TESTはTest7/8を含む全13判定で`PASS=0D FAIL=00`。
  ただし、その後の最終SDRAM要求受理修正後の再実行結果は未報告。
- 最終SDRAM要求受理修正後、LD24MIはリセット直後も安定して
  `PASS=13 FAIL=00`。`13`は16進数で19判定を表す。
- SofaRun経由でスペースマンボウの起動・動作を確認したとの実機報告あり。
  長時間プレイや音源を含む網羅的な互換性確認とは区別する。
- 要求受理RTL回帰18ケース、Z80X24版・標準版の論理合成は成功。

詳細は[解決レポート](24bit拡張メモリ_バス分離と要求受理競合_解決レポート_2026-10-23.md)を参照。

## 2. 仕様変更前の実機回帰

同じ最終修正FPGAを使用し、結果・実行条件を記録する。

- [ ] **P24TEST**: `PASS=0D FAIL=00`。
- [ ] **電源を切って再投入した直後のLD24MI**: `PASS=13 FAIL=00`。
      ソフトリセット直後の合格とは別に確認する。
- [ ] **P12TEST**: モード間制御の既存8判定がすべてPASSし、DOSへ正常復帰する。
- [ ] **P1314TEST**: 旧仕様の割込み・RSTの全7判定で`PASS=07 FAIL=00`。
- [ ] 結果とFPGAソース/ビルドの対応を記録し、変更前の安定点を保存する。
      コミット・タグを使う場合はユーザー承認後に行う。

記録項目:

- FPGAビルドを識別できる情報と使用したCOMの版
- 電源再投入/リセット/連続実行の区別と実施回数
- PASS/FAIL集計、失敗時のgot/want、停止位置、DOS復帰の可否

FAILがあれば先に切り分け、新割込み仕様を重ねて修正しない。

## 3. 合意済みの新仕様の方向

以下は設計上の合意・方針であり、現行RTLへ反映済みという意味ではない。

- 割込みバンクを一つに統一する。仮称は8bitの`IBR`。
- M2のIM1 IRQは`IBR:0038h`、NMIは`IBR:0066h`へ分岐する。
- M2のIM2は、IBR内の`(I << 8) | 割込みベクタ値`から
  2byteの分岐先を読み、同じIBR内へ分岐する。
- 拡張RST命令も共通のIBRを使用する。
- M0/M1のIM0/IM1/IM2は従来のZ80互換を維持する。
- **M2中のIM0命令はNOP扱い**とし、現在のIM設定を変更しない。
- **IM0設定のままM2へ入った場合は、M2中のIRQだけIM1相当として処理する。**
  IM設定自体は保持する。これだけでIFFや割込み許可状態は変更しない。
- M2中にIM1/IM2を実行した場合、その設定変更は残る。
  モード復帰で以前のIM設定を自動復元する仕様ではない。

## 4. RTL変更前に確定する仕様

- [ ] IBRの名称、設定/読出し命令、リセット値。
- [ ] 旧IVR24/NVR24/RST_Bと関連命令の廃止・互換性・予約opcodeの扱い。
- [ ] 通常RSTと拡張RSTの違い、M0/M1での拡張RSTの動作。
- [ ] IM2ベクタ取得バスサイクルと、IBR内のテーブル読出し手順。
- [ ] テーブル位置`FFFFh`から2byteを読むときの折返し規則。
- [ ] IM0のミラーopcodeを含む無効化範囲。
- [ ] IRQ/NMIの保存フレーム、IFF操作、復帰命令とハンドラのモード。
- [ ] SYSCALLを採用するか、そのopcodeと動作範囲。

### SYSCALLの検討案 (未確定)

即値8bitを持つ`SYSCALL n`で、IM2と同じテーブル参照回路を使う。
案では`n`はバイトオフセットとし、重ならない2byteエントリなら偶数値を使って
128入口を設ける。256個の呼出し番号が必要なら別途索引計算を定義する。

提案中の動作:

- M2のみ対応し、テーブル/分岐先のバンクはIBRを使用。
- 実際の割込み応答バスサイクルは出さない。
- IFF1/IFF2は変更しない。
- MSP24へPC24とモードの4byteフレームを保存し、`RET.M`で復帰。

これらの細部はまだ承認・確定していない。
特権や保護機構を伴わない限り、SYSCALL自体をセキュリティ境界とは扱わない。

## 5. テストの改訂方針

| 対象 | 方針 |
|---|---|
| LD24MI | 維持し、SDRAM/通常アクセス/境界またぎの回帰に使用 |
| P24TEST | 維持し、PUSH24/POP24とMSP24の回帰に使用 |
| P12TEST | 基本は維持。必要に応じてハンドラとのモード復帰を追加 |
| P1314TEST | 共通IBR、IRQ、拡張RSTの新仕様に合わせて改訂 |
| LD24Test | IVR/NVR転送など変更対象の判定を改訂。現行結果の記録も照合 |
| IM2/SYSCALL | 専用RTL試験を追加し、その後に安全な実機試験を作成 |
| 通常MSX互換動作 | DOS復帰、SofaRun、ゲームの起動・継続動作を回帰確認 |

### 新仕様で必須とする試験

- [ ] M0/M1のIM0/IM1/IM2と通常NMI動作が維持される。
- [ ] M2のIM1、IM0から引き継いだIRQ、NMIが指定IBRの固定入口へ分岐する。
- [ ] M2でのIM0実行はIM1/IM2設定を変えない。
- [ ] IM0設定からM2へ入り、設定変更せずM0/M1へ戻るとIM0が維持される。
- [ ] IM2はIレジスタ・ベクタ値・IBRを正しく使い、16bit分岐先を正しい順で取得する。
- [ ] IBRと実行元PC/データ用バンクを異なる値にして、参照元の取り違えを検出する。
- [ ] テーブル末尾・保存スタックのバンク境界で期待どおり動作する。
- [ ] 拡張RSTの全8入口が共通IBRへ分岐し、復帰先とスタックが復元される。
- [ ] IRQ/NMIのIFF変化、DI/EI、HALT解除、復帰命令の挙動を確認する。
- [ ] 実機NMI入力が固定の間は、実NMI受付を実機検証済みと記録しない。
- [ ] SYSCALLを採用する場合、テーブル参照、次命令への復帰、IFF不変、
      不要な割込み応答サイクルが出ないことを検証する。
- [ ] ハンドラ/テーブル読出しでも通常MSX側デコーダへの副作用がない。

## 6. 実装と完了判定

1. 上記「仕様変更前の実機回帰」を完了し、安定点を保存する。
2. 未確定仕様と期待結果を明文化する。
3. 新仕様のRTL試験を作成し、対象機能を段階的に実装する。
4. 対象試験と既存回帰、論理合成・配置配線の確認を行う。
5. 新仕様用の実機テストと、維持した既存テストを実行する。
6. リセット/電源投入直後の結果と通常MSX互換動作を含めて記録する。

現行テストのPASS数を、新仕様へ改訂したテストの期待値として無条件に流用しない。
網羅的な全バンクメモリ試験などは別の強化項目であり、この仕様変更前の
短い回帰を完了するための必須条件にはしない。
