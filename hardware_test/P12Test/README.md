# Z80X24 Phase12 モード間制御 実機検証テスト (P12TEST.COM)

MSXnano-Z80X ([msxnano-24bit](../..) リポジトリ、24bit CPU拡張 "Z80X24") の
**Phase12「モード間制御」**(`JP.M0`/`M1`/`M2`, `CALL.M0`/`M1`/`M2`, `RET.M`) を、
実機(Tang Nano)またはMSXエミュレータ上のMSX-DOS(2)から起動して確認するための、
Z80アセンブリ製テストプログラムです。

同じ対象命令を検証するGHDLシミュレーション版テストベンチが
`msxnano-24bit/fpga/G80A/test/tb_phase12_mode_control.vhd` にあります。本プログラム
はそれを実機上で再現します。

## 必要な環境

- Windows
- Z88DK (`D:\Tool\z88dk` にインストールされている想定)
- `z88dk-z80asm` / `z88dk-appmake`
- `make` (GnuWin32 make等)
- 実行環境としてZ80X24拡張済みMSXnano実機、またはMSX-DOS(2)が動くMSXエミュレータ

PowerShellで現在のターミナルだけPATHへ追加する場合:

```powershell
$env:Path += ";D:\Tool\z88dk\bin"
```

コマンドが見つかることを確認します。

```powershell
Get-Command z88dk-z80asm
Get-Command z88dk-appmake
```

## ビルド

`P12Test` フォルダで実行します。

```powershell
make
```

`bin\p12test.com` が生成されます。中間ファイルは `obj` と `BINZ80` フォルダに
生成されます。`make clean` で中間ファイルを削除できます。ビルドはこの環境で
実際に実行し、エラー・警告なくアセンブルできることを確認済みです(919byte)。

`build.bat` は `z80asm` を直接呼び出す簡易スクリプトです(Z88DK同梱の
旧来の `z80asm` 用で、環境によっては使えない場合があります)。標準の
ビルド手順は `make` です。

## MSX上での実行

`bin\p12test.com` をMSXまたはエミュレータのディスクイメージ(または実SDカード)
へコピーし、MSX-DOSから実行します。

```text
A>P12TEST
```

実行ファイル名はMSX-DOSの8.3形式に合わせて `P12TEST.COM` としています。

## テスト内容

`p12_test.asm` は以下の6テスト(Test1/2はそれぞれa/bの2チェックに分かれるため
合計8件のチェック)を順に実行し、各チェックの結果と最後に合計PASS/FAIL数を
画面へ表示します。Phase12で実装した7個のモード間制御命令
(`ED 93`-`99`: `JP.M0`/`M1`/`M2`, `CALL.M0`/`M1`/`M2`, `RET.M`)すべてを
少なくとも1回ずつ実行します。

| # | 内容 |
|---|---|
| Test1a/1b | `JP.M0 addr16` (`ED 93`)。M1からM0へ切替わることを確認する。`mode24`自体を直接読み出す命令は存在しないため、切替え直後に行う`(HL)`書込みが「拡張bankを無視したflatな書込み」になる(=bank01hへは書かれず、常にbank00hへ書かれる)ことを通じて間接的に確認する |
| Test2a/2b | `JP.M1 addr16` (`ED 94`)。M0からM1へ切替わることを、Test1と逆方向の書込み挙動(bank01hへ"bank対応"書込みされる)で確認する |
| Test3 | `JP.M2 addr24` (`ED 95`)。物理bank02hへ実際に小さなサブルーチンのバイト列をbank-aware `(HL)`書込みで1byteずつコピーし、そこへ`JP.M2`でジャンプして実行させ、専用のマーカー変数が書き換わることで「正しい物理bankへジャンプして実行した」ことを確認する(実行マーカー方式)。コピー先のコードは最後に`JP.M1`で安全にbank00hへ戻ってくる |
| Test4 | `CALL.M0 addr16` (`ED 96`) + `RET.M` (`ED 99`)。bank00h内で完結する呼出し/復帰往復試験。呼出し先がマーカー変数を書き換え、`RET.M`で正しく復帰することを確認する |
| Test5 | `CALL.M1 addr16` (`ED 97`) + `RET.M`。Test4と同じ形だが`CALL.M1`版 |
| Test6 | `CALL.M2 addr24` (`ED 98`) + `RET.M`。物理bank02hへサブルーチンをコピーし、`CALL.M2`で呼び出し、呼出し先が`RET.M`で復帰することを確認する(実行マーカー方式 + 往復)。`CALL.M2`はPhase12の中でも最後に実装された命令で(1opcode+3byte addr24フェッチ+4byte戻りフレームpush=8 MCycle必要。T80コアの`MCycle`信号を3bit→4bitへ拡張して実装。詳細は[T80コア内部に残っていた潜在バグ_Phase11-12での発見と修正.md](../../doc/jpn/T80コア内部に残っていた潜在バグ_Phase11-12での発見と修正.md)参照)、本テストはそれを実機で初めて検証するものである |

全テストがPASSすれば、Phase12で実装したモード間制御命令群が、仕様書
([MSX_T80_24bit化_CPU仕様書_V8](../../doc/jpn/MSX_T80_24bit化_CPU仕様書_V8_2026-10-05.md))
および[AVAILABLE_INSTRUCTIONS.md](../../AVAILABLE_INSTRUCTIONS.md)セクション10
どおりに動作していることが実機で確認できます。

> **実機検証状況**: 2026年10月にビルド(エラー・警告なし)を確認済み、
> さらに実機(Tang Nano)上で実行し、**全8チェックがPASSしました
> (`PASS=08 FAIL=00`)**。これにより、Phase12のモード間制御命令群
> (`JP.M0`/`M1`/`M2`, `CALL.M0`/`M1`/`M2`, `RET.M`)すべて、特に
> MCycle幅拡張(3bit→4bit)で追加実装した`CALL.M2`も、実機で正常に
> 動作することが確認できました。

## 本増分の対象範囲・既知の制約

- `mode24`自体を直接読み出す命令は存在しないため(`AVAILABLE_INSTRUCTIONS.md`
  の「`PC_B`も直接LDする命令は無く...」の記述のとおり)、Test1/2は
  「アドレッシング挙動の違い」という間接的な方法でモード切替えを確認して
  います。Test4/5のRET.M復帰後のモード復元については、GHDLテストベンチ
  (`tb_phase12_mode_control.vhd`)で既にbit単位の厳密な一致を検証済みのため、
  本プログラムでは「呼出し先のマーカー実行」のみを確認し、モード自体の
  再確認は行っていません(Test1/2と同じ手法を使えば可能ですが、本プログラム
  ではテスト規模を抑えるため割愛しました)。
- Phase13(M2割込み拡張)は本リポジトリでまだ未実装です。そのため本プログラム
  はM1/M2モードでの拡張アドレッシング区間を必ず`DI`/`EI`で囲み、割込みが
  M2中のPC拡張bank実行や4byte戻りフレームのpush/pop途中に入り込まない
  ようにしています(詳細は下記「安全上の注意」参照)。

## 安全上の注意

- **M1/M2モードでバンクレジスタを設定した状態のままBIOS/DOSコールを行うと、
  BIOS/DOS側が内部で使う`(HL)`等のアクセスまで拡張メモリへ誤ってリダイレクト
  される危険がある**ため、[MMUTest](../MMUTest)の先例に厳密に従い、本プログラムは
  「`DI`→`SET_M1`/`M2`またはモード切替え命令本体のテスト(BDOS呼出しは一切
  行わない)→`SET_M0`→`EI`」という区間だけ拡張アドレッシング/M1/M2モードを
  使い、画面出力やBDOS呼出しは必ずM0へ戻してEIした後に行います。
- `JP.M2`/`CALL.M2`で実際にジャンプ・コールする先の物理bank02hのコードは、
  本プログラム自身の(bank00hの)データ領域内に用意したテンプレートバイト列を、
  bank-aware `(HL)`書込みで1byteずつコピーしたものです。コピー先アドレス
  (`TARGET_CODE=8000h`)はbank02hという、本プログラムの64KB空間とは完全に
  別の物理メモリ上の未使用オフセットなので、本プログラム自身やBIOS/DOSの
  既存コードを破壊する心配はありません。
- 拡張メモリアクセスで使用する物理bankは **01h**(MSP24スタック/Test1,2の
  スクラッチ)・**02h**(JP.M2/CALL.M2コピー先コード)**のみ**です。これは
  `fpga/top.v` の `CPU_SDRAM_BASE`(0x640000)経由で、既存のMemory Mapper
  (0x000000-)やMegaRAM(0x400000-)とは重ならない安全な領域(0x650000以降、
  詳細は`doc/jpn/SDRAMメモリマップ.md` 2.2章)に収まります。
- `CALL.M0`/`M1`/`M2`・`RET.M`が使うMSP24は`01:E000h`に設定します
  ([Push24Test](../Push24Test)等と同じ安全な初期値)。PUSH24/POP24と異なり、
  `CALL.Mx`の4byte戻りフレームpushは単一物理bank内で完結します(MSP24が
  `E000h`から`DFFCh`までしか動かず、bank境界をまたがない)。そのため
  `Push24Test`のREADMEに記載されている「bank境界またぎPUSH24/POP24で
  実機フリーズする既知の問題」には抵触しない設計です。
- プログラム終了前に、必ずM0へ戻し使用したバンクレジスタ(`HL_B`)を0クリア
  してからMSX-DOSへ復帰します(`SAFE_RESET`参照)。本プログラムが使用する
  バンクレジスタは`HL_B`のみで、`BC_B`/`DE_B`/`IX_B`/`IY_B`は一切変更して
  いません(既定値の00hのまま)。
- Z80X24拡張が入っていない通常のMSX実機/エミュレータ上で実行すると、
  `ED 90`〜`ED 99`や`ED 24/2C`は未定義命令(多くの実装ではNOP相当)として
  扱われます。この場合、全テストがFAILと表示されますが、これは異常ではなく
  「拡張機能が存在しない」ことを意味します。

## ファイル構成

- `p12_test.asm` — テスト本体
- `makefile` — `z88dk-z80asm` + `z88dk-appmake` によるビルド
- `build.bat` — 旧来の `z80asm` を直接呼び出す簡易スクリプト
- `bin/` — ビルド成果物 (`p12test.com`)
- `obj/`, `BINZ80/` — 中間ファイル・リストファイル
